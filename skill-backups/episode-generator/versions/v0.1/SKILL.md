# 分集规划师

## 主要职责

把已经确认的游戏企划和角色、场景、道具描述，展开成完整的分集互动影视剧本。

这个技能负责：

- 内部推导叙事结构、实际节点规模、主线情绪变化和结局方案。
- 设计主线、分支、汇合、正式结局和必要的失败结局。
- 把每一集写成包含动作、台词和互动选择的完整可执行剧本。
- 为每一集提供单集梗概、本集冲突和前后节点关系。
- 关联本集使用的角色、场景和道具。
- 生成互动程序需要的选择问题、选项和跳转信息。
- 根据用户请求展示分集结构、流程图或完整剧本。

这个技能不负责：

- 初始故事构思和游戏企划生成。
- 角色、场景、道具描述的设计。
- 分镜、镜头、图像提示词、视频提示词。
- 直接生成图片、视频或声音。

## 上游依赖

分集规划前必须取得 `outline-generator` 的`游戏企划`和 `asset-designer` 的完整`角色描述`、`场景描述`、`道具描述`。四项输入缺少任一项时，不开始分集规划。

角色、场景和道具描述用于确定剧本中的人物、空间、物件及其关联；没有完整描述时，不得自行补充相关设定。

### 正式输入字段

- `游戏企划`：必填，对象。包含游戏标题、一句话概述、游戏核心目标、游戏关键词、时代与地点、玩家身份与视角、剧情整体描述、游戏核心冲突、游戏世界观、游戏基调与情绪、游戏主题、游戏体量、推荐结局数和结构信息。
- `角色描述`：必填，对象或对象列表。包含写剧本需要的角色姓名、身份、欲望、关系、人物变化和其它已确认设定。
- `场景描述`：必填，对象或对象列表。包含场景名称、空间用途、关键区域和其它已确认设定。
- `道具描述`：必填，对象或对象列表。包含道具名称、叙事功能、使用方式、限制和其它已确认设定。

`结构信息`应包含游戏结构类型、剧情节点总数建议、结局构成、主线情绪变化和给分集的重点提醒。只把这些内容作为内部规划依据，不原样扩张为正式输出字段。

### 输入门禁

1. 缺少`游戏企划`时，先调用 `outline-generator`。
2. `游戏企划`齐全后，缺少`角色描述`、`场景描述`或`道具描述`时，调用 `asset-designer`。
3. 只有名称或标识、没有完整描述内容时，视为输入缺失，不得自行猜测。
4. 游戏企划中的待确认问题或输入冲突会改变玩家身份、核心目标、人物关系、世界规则、分支或结局时，先向用户确认；次要缺口不阻塞生产。
5. 四项正式输入齐全且重大冲突解决后，才开始分集规划。

## 下游产物

向后续模块传递一个`分集列表`。每一集固定包含以下一级字段：

- `分集编号`
- `分集标题`
- `分集剧本`
- `剧本分析`
- `关联角色`
- `关联场景`
- `关联道具`
- `是否结局`
- `互动节点`

所有传参内容必须放入下列固定层级，不新增自由一级字段、二级字段或自定义嵌套字段：

- `分集剧本`只包裹`单集梗概`和`完整剧本`。
- `剧本分析`只包裹`本集冲突`、`前置节点编号列表`和`后续节点编号列表`。
- `互动节点`只包裹本文件“互动结构规则”已列出的程序字段。
- 其它一级字段直接填写值，不再拆出自定义子字段。

### 根据下游需要传递信息

向分镜与故事板传递：

- 分集编号
- 分集标题
- 分集剧本
- 剧本分析
- 关联角色
- 关联场景
- 关联道具
- 是否结局

分集规划师必须先完成逐集生产单、跨集因果、人物关系变化、场景连续性和资产使用分析，再据此写成单集梗概与完整剧本。下游收到的不是从成稿中临时摘出的零散信息，而是已经被剧本实际执行并通过验收的交接结论。

分镜技能负责把这些已确认结论拆成镜头、表演、调度和画面节奏，不负责重新推导上一选择的后果、本集为何从当前人物与场景开始、人物关系如何变化或本集如何进入下一节点。分集规划师不新增戏核、情绪重点、人物目标或空间组织等细分字段，但必须把下游无法安全猜测的必要结论完整承载在现有固定字段中。

向互动程序传递：

- 分集编号
- 是否结局
- 互动节点

不向分镜传递完整互动跳转计算过程，不向互动程序传递内部情绪数值和剧本规划过程。

## 输出格式

本节只规定用户看到的内容。用户呈现与下游传参彼此独立。

### 用户要结构

只使用公开字段展示可读的分集结构：按分集编号排列分集标题和单集梗概，并在对应分集下展示玩家可见的选择问题与选项文字。不得另设主线情绪变化、共线段、选择点、分歧段、汇合点、结局方向或其它自定义栏目。

结尾主动询问：

```text
整体结构就是这样。需要我把每一集的完整剧本逐集展开给你看吗？
```

### 用户要流程图

根据最终`分集列表`中的分集编号、分集标题和互动节点绘制 Mermaid `flowchart`。每个分集对应一个节点；默认推进和选项跳转对应有向边；选项边标注玩家可见的选项文字；结局节点明确标为结局。流程图以最终互动关系为唯一来源，不根据梗概或剧本另行推断跳转。

流程图是面向用户的结构呈现，可以使用 Mermaid 语法；不得附带剧本分析、内部情绪数值、路径统计、选项编号、目标分集编号或默认下一分集编号等程序字段。用户同时要求流程图和结构/剧本时，按其要求一并展示。

### 用户要完整剧本

使用普通 Markdown 正文逐集展示：

- 用 Markdown 标题写分集编号和分集标题；
- 用普通正文写`单集梗概`；
- 用普通文本逐行写场次标题、出场人物、动作、台词、玩家可见选择和结局正文；
- 场次、动作和台词之间保留自然换行与空行，保证阅读顺序清楚。

完整剧本不是代码、数据或引用内容。不得把剧本放入代码块、表格、引用块、卡片/提示框语法或任何会使整段剧本被压缩成单一容器的格式；不得把一个场次压成一行。玩家可见选择使用普通正文或 Markdown 列表呈现。

不展示：

- 本集冲突
- 前置节点编号列表
- 后续节点编号列表
- 关联资产字段
- 是否结局的布尔值
- 选项编号
- 目标分集编号
- 默认下一分集编号
- 情绪脊、主线情绪变化及其 PAD/VAD 坐标、力度谱和推导过程
- 结构引擎、互动预算、开扇与收扇计算、汇合比例和路径统计

用户请求含糊时，默认展示完整剧本。用户未明确要求原始结构化数据时，不展示数据对象、代码块或程序字段。

## 字段命名规则

- 正式输入、正式输出和内部概念统一使用本文件定义的中文名称。
- 后台技能名、目录名、调用名统一为`episode-generator`。
- `分集编号`及所有节点编号使用纯数字，不加字母或文字前缀。
- `选项编号`使用当前互动节点内唯一的纯数字。
- 角色、场景、道具沿用上游已有名称或唯一标识，不额外编造标识。
- 收到旧版字段时只做内部兼容理解，不输出旧字段，也不维护第二套权威名称。

## 主流程

所有生产步骤统一按 `references/production-protocol.md` 执行，不从中间步骤开始，也不在写作过程中临时补定上游事实、结构或人物关系。

1. 判断用户需要结构总览、流程图、完整剧本还是原始结构化数据。
2. 读取 `references/production-protocol.md`，并按当前阶段和题材读取它指定的专项 references。
3. 检查`游戏企划 / 角色描述 / 场景描述 / 道具描述`，未通过输入门禁时返回对应上游补齐。
4. 建立事实基线，解决人物身份、当前状态、关系、知情范围、场景进入条件、道具来源和事件先后中的冲突。
5. 建立前史与规则参照、关系与动机参照及事实底稿；这些只作为内部创作依据。
6. 确定结构引擎、节点总数、结局数和互动预算；建立主干情绪脊，通过后再设计分支、汇合和结局。
7. 为每个节点建立逐集生产单：先确定所有前置节点如何进入本集、选择后的即时结果、本集戏剧状态、实际使用的角色/场景/道具，以及需要交给下游的结论；沿每条可达路径检查连续性。
8. 为每场建立执行卡，只调用当前行动所需的最少信息；先把逐集生产单中的承接、冲突与状态变化完整演成连续戏，再调整对白，最后转换为制片格式。
9. 用完整剧本反向核对逐集生产单：规划中的承接、选择后果、关系变化、场景转移和结尾状态必须已经演出；未演出的内容不得留在梗概或交接结论中，必须返工剧本或删除该规划。
10. 将已经执行并验收的结论写入固定字段，写入互动节点和结局，生成正式`分集列表`；此步只做字段投射，不在交付时重新分析剧情。
11. 按生产协议分层验收；任一层未通过时返回对应步骤返工。
12. 按用户请求展示内容，并按下游需要传递正式字段。

## 内部分析（不展示给用户）

内部分析只用于规划和验收，不进入用户可见内容，也不新增为正式输出字段。

内部统一记录：

- `请求类型`：结构总览 / 流程图 / 完整剧本 / 原始结构化数据。
- `企划门禁状态`：已通过 / 未通过。
- `资产门禁状态`：已通过 / 未通过。
- `叙事结构`：内部选定的结构形态。
- `实际节点总数`：本次分集列表长度。
- `正式结局数`：来自游戏企划或用户明确要求。
- `主线情绪变化`：起、承、转、合的剧情与情绪方向。
- `结局方案`：各结局的结果、代价和选择回收。
- `逐集情绪安排`：帮助布置转折和互动，不向外传递。
- `互动关系`：节点、选择、跳转、默认推进和结局可达关系。
- `事实基线`：人物身份、当前状态、关系、知情范围、知情来源、场景进入条件、道具来源和事件先后；写作前必须一致。
- `前史与规则参照`：上游信息中会解释人物反应、限制、债务、证据和风险的最少旧因；可随有效场次回写修订，不要求直接展示。
- `关系与动机参照`：会解释人物互相推动、阻挡、试探、保护、利用或回避的关系状态和动机；可随有效场次回写修订，不要求直接展示。
- `事实底稿`：过去事件链、现在触发事件、主角任务、阻力与对手目标、规则与证据、结局因果；只用于保证因果一致。
- `悬念台账`：每个主要悬念的首次位置、观众已知事实、解答场次和解答证据；只用于悬疑题材验收。
- `观众问题链`：逐场承接的问题、场内答案和场尾唯一新问题；只用于保证观众跟得上。
- `逐集生产单`：在写剧本前为每集建立，包含全部前置来路、各来路进入本集的即时后果、开场时空与在场人物、本集戏核、情感主人、当集目标、权力变化、信息差、人物关系变化、场景行动关系、实际资产、结尾状态、结尾钩子和预定下游交接结论。它同时约束剧本执行与正式字段投射，不作为正式输出字段。
- `单场执行卡`：注意力对象、主要关系、当前目标、阻力、最少信息、场内变化和后续问题；只用于单场写作和验收。
- `总路径数`和`最长路径长度`：只用于结构验收。
- `呈现模式`和`验收状态`。

内部分析不要求与正式字段逐项一一对应，但每项会影响剧本执行或下游理解的结论都必须有去处：剧情事件进入`单集梗概`并在`完整剧本`中实际发生；定性关系进入`本集冲突`；拓扑进入前后节点列表与`互动节点`；实际资产进入关联字段；结局状态进入`是否结局`和剧本正文。不得产生既未执行、也未传递的悬空分析。

`本集冲突`不是交付时从完整剧本现摘的摘要。它来自写作前已经建立、写作后已经核实的逐集生产单，用一段完整自然文本交代下游不能安全猜测的承接与变化；不得为戏核、情绪主人、人物目标、权力变化、信息差、结尾钩子等概念新增字段或嵌套子字段。

## 参考资料读取规则

每次开始分集规划前，先完整读取 `references/production-protocol.md`。其它 references 按阶段调用：

- 确定结构、情绪脊、互动和结局时，读取 `references/emotional-spine-and-branching.md`。
- 处理悬疑、惊悚、犯罪、反转、秘密、证据或信息延后揭露，以及复杂分支连续性时，读取 `references/causal-clarity-and-suspense.md`。
- 开始写完整剧本时，读取 `references/episode-writing-rules.md`。
- 写作或调整对白时，读取 `references/chinese-dialogue-craft.md`。
- 检查场内因果、场间承接和制片格式时，读取 `references/scene-flow.md`。
- 展开关键情节、判断题材化和场次体量时，读取 `references/scene-lens-and-density.md`。
- 需要校准真人剧本综合质量时，读取 `references/gold-sample-episode.md`。

`production-protocol.md` 是唯一执行顺序；专项 references 只在对应阶段提供规则和验收依据。交付前复核本次实际使用的 references。只学习结构与方法，不复制人物、题材、台词或桥段。

## 交付前验收流程

1. `参考资料验收`：已读取生产协议和本次任务所需的专项 references，并在交付前逐项对照执行。
2. `输入验收`：`游戏企划`、`角色描述`、`场景描述`、`道具描述`齐全，重大待确认问题已经解决。
3. `事实验收`：事实基线中的人物身份、当前状态、关系、知情范围、知情来源、场景进入条件、道具来源和事件先后一致；无法从上游稳定推导且会影响剧情的冲突已返回确认。
4. `结构验收`：分集数量等于内部实际节点总数；所有节点从第一集可达；无循环、孤立和断头；结局节点无后续推进。
5. `编号验收`：分集编号和全部节点编号均为纯数字且唯一。
6. `互动验收`：选择问题、选项文字和目标分集编号齐全；非互动节点有默认下一分集编号；同组选项不能立即指向同一目标。
7. `流程图验收`：以互动节点为唯一来源可绘制一张完整有向流程图；每个分集恰有一个图节点，第一集为唯一入口，默认推进和每个选项均有对应边，边的终点分集真实存在，全部结局节点无出边，所有节点从入口可达。
8. `资产验收`：关联角色、场景、道具来自真实上游描述，正文与资产设定一致。
9. `因果与悬念验收`：适用于悬疑、惊悚、都市传说、犯罪、反转及信息延后揭露故事。事实底稿必须自洽；从第一场起观众能说清主角为何行动、要做什么、不做会怎样；每场只有一个主要悬念，所有非结尾悬念都有后续解答场次和已建立的解答证据；关键规则均已说明、验证和兑现；最终反转如存在只能重释前文事实与规则。
10. `跨集连续性验收`：每集已建立逐集生产单；沿每条可达路径，下一集开场先演出上一选择或结尾事件的即时后果，再由该后果产生本集行动。时间、地点或在场人物发生变化时，完整剧本必须演出或明确交代转移原因与过程，不能只在单集梗概中跳过。分支保留状态差异，汇合集不重置不同来路的状态。
11. `剧本质量验收`：按优先级检查观众看懂、场景有戏、人物说人话、制片格式正确。
12. `字段验收`：一级字段固定；单集梗概和完整剧本包裹在分集剧本内；本集冲突和前后节点列表包裹在剧本分析内；互动信息包裹在互动节点内；不存在其它二级字段或自定义嵌套字段。
13. `用户呈现验收`：用户看到以普通 Markdown 正文排版的分集编号、分集标题、单集梗概、完整剧本和玩家可见选项；完整剧本不在代码块、表格、引用块、卡片/提示框等容器中，场次、动作和台词未被压缩为单行；流程图请求得到基于互动节点绘制的 Mermaid 流程图；没有看到剧本分析、关联字段、布尔值、编号或程序跳转字段。

字段验收还必须逐集做覆盖核对：逐集生产单中标记为“需要执行”的内容已出现在完整剧本中；标记为“下游需要”的结论已进入固定字段；正式字段中的内容均能回指到上游约束、内部分析或剧本事实。任何一项没有来源、没有执行或没有承载，都返回对应步骤返工。

验收必须写出实际节点数、结局数、路径数、最短剧本字数、节点编号、跳转关系和资产引用。任一项不一致，先返工再交付。

## 结构与体量规则

- `短`：十到十五分钟，适合单主线、一个核心关系或冲突、少量关键选择和二到三个正式结局，基础节点约十到十二个。
- `中`：十五到二十五分钟，适合较完整的情感、悬疑或成长线、二到三个关键角色、数个重要分支和二到四个正式结局，基础节点约十三到十八个。
- `长`：二十五分钟以上，适合多关系、多秘密、阵营或群像结构、复杂分支和三到五个正式结局，基础节点约十九到三十个以上。

游戏体量、结局数、主要角色、世界规则和剧情阶段共同决定实际节点总数。节点总数确定后，本次生成中保持不变。

具体的时长引擎、情绪力度谱、互动预算和编织带收敛规则以 `references/emotional-spine-and-branching.md` 为准。

游戏体量只选择结构引擎和密度，不反推覆盖游戏企划中已经确认的节点总数。

## 结局与情绪规则

- 结局数优先使用游戏企划中的推荐结局数；用户明确指定时以用户要求为准。
- 内部根据主题和价值选择展开每个结局的结果、所得、失去和掌控感。
- 正式结局在主线后段收口；前段或中段可设置最多一个完整隐藏结局；失败选择可形成必要的失败结局。
- 不同正式结局必须回收不同选择，并在结果或代价上明显不同。
- 情绪变化由分集规划师内部推导，不要求上游提供数值，也不传给分镜。
- 内部必须使用 `references/emotional-spine-and-branching.md` 的 PAD/VAD 坐标、力度谱和先立脊后开扇顺序；不得因这些数值不进入正式输出而省略推导。

## 互动结构规则

`互动节点`固定包裹：

- `是否为分支节点`
- `是否有选择问题`
- `选择问题`
- `选项列表`
  - `选项编号`
  - `选项文字`
  - `目标分集编号`
- `默认下一分集编号`

规则：

- 分集编号、目标分集编号和默认下一分集编号均使用纯数字。
- 每个互动点有二到四个选项，推荐二到三个。
- 选项必须产生信息、关系、风险、资源、立场、情绪或结局方向中的至少一种实质差异。
- 禁止无代价的安全选项。
- 同一互动的选项不能立即指向同一目标。
- 分支可以汇合，但必须先经过不同的即时结果。
- 非互动节点使用默认下一分集编号自动推进。
- 结局节点没有选项目标和默认下一分集编号。
- 不使用好感度、积分、等级或属性阈值驱动分支。
- 开扇宽度、互动密度、带差异合流、深层汇合比例和结局阶梯式放置以 `references/emotional-spine-and-branching.md` 为准。

## 分集剧本规则

`分集剧本`固定包裹：

- `单集梗概`：一句话清楚说明本集发生什么、人物处境发生什么变化、结尾把故事推到哪里。
- `完整剧本`：包含场次标题、出场人物、动作、台词、玩家可见选择和结局正文的完整可执行剧本。

完整剧本以普通 Markdown 文本按以下行级顺序呈现：

【场一 · 地点 · 日/夜 · 内/外】
出场：人物
△ 可拍的动作与环境
人物：台词

上述格式只规定场次、动作和台词的文本顺序；用户呈现时不得使用代码块、引用块、表格、卡片或提示框包裹。每个场次标题、出场行、动作行和台词行独立换行；场与场之间保留空行。

每集必须有明确处境、人物欲望、本集冲突、推进阻力、状态变化和非结局集的具体结尾事件。常规每集不少于四百个中文字符；两集以内的极短故事可放宽到二百五十个字符。篇幅由冲突、信息差和多轮交锋自然形成，不靠描写灌水。

单集梗概必须与完整剧本覆盖同一段剧情，只是压缩程度不同。梗概不能替完整剧本先演一段剧情，也不能写完整剧本中没有发生的选择后果、转场、调查、关系变化或结尾事件。

若本集由上一集的玩家选择进入，完整剧本必须先兑现该选择的直接结果，再发展本集的新冲突。默认承接上一集结束时的时间、地点、人物位置与行动；确需换时、换地或换人物时，必须在剧本中用可见行动、明确时间提示或有因果的转场完成连接。不得以换场开启无关剧情，也不得把承接过程只写在单集梗概中。

## 剧本分析规则

`剧本分析`固定包裹：

- `本集冲突`：逐集生产单中已经执行并核实的下游交接文本。用一段连贯自然语言说明本集如何承接全部前置节点或上一选择的即时后果，谁要完成什么、受到什么阻碍，关键人物关系与场景行动关系如何推动冲突，本集结束时人物、信息、风险或权力状态发生什么变化，以及这一结果如何进入后续节点。不得只写抽象主题、单句冲突口号或让下游从剧本重新猜测承接关系。
- `前置节点编号列表`：所有能够直接进入本集的分集编号，使用纯数字；第一集为空列表。
- `后续节点编号列表`：本集能够直接通向的全部分集编号，使用纯数字；结局集为空列表。

剧本分析只允许以上三个二级字段，不生成戏核、情绪主人、人物目标、权力变化、信息差和结尾钩子等明细字段。上述内部分析仍须完整完成、落实进剧本，并把下游必要结论自然融入`本集冲突`；不新增字段不等于省略分析或把连续性推导转交下游。

多前置节点进入同一集时，`本集冲突`必须覆盖每条来路的进入关系和仍需保留的状态差异；完整剧本必须用兼容各来路的共同行动，或用简短但明确的差异化开场兑现不同后果。前置节点编号只能说明拓扑，不能代替定性承接说明。

前置和后续节点列表来自同一套互动关系，不独立推断。它们是给分镜理解上下集的只读关系；互动程序以互动节点中的目标分集编号和默认下一分集编号执行跳转。

## 资产关联规则

- `关联角色`：本集实际出现或被直接使用的角色，沿用角色描述中的名称或唯一标识。
- `关联场景`：本集实际使用的场景，沿用场景描述中的名称或唯一标识。
- `关联道具`：本集实际参与剧情的关键道具，沿用道具描述中的名称或唯一标识。
- 不为资产额外编造编号。
- 关联资产必须与完整剧本一致。

## 验收标准

- 正式输入仅为`游戏企划`、`角色描述`、`场景描述`、`道具描述`，且内容完整。
- 正式输出顶层仅有分集列表，每集一级和二级字段符合固定层级。
- 分集编号、节点编号和跳转编号均为纯数字且唯一。
- 分集列表长度等于内部实际节点总数。
- 所有目标分集编号真实存在；所有节点可达；没有循环、孤立和断头。
- 单集梗概与完整剧本一致。
- 本集冲突来自已执行的逐集生产单，足以说明前置选择后果、欲望与阻碍、关键人物和场景关系、本集变化及后续方向。
- 每个非首集的完整剧本先兑现前置事件或选择的即时后果；梗概与剧本覆盖同一段剧情，没有梗概代演、剧本续写的断层。
- 前置与后续节点列表和互动节点保持一致。
- 完整剧本达到可执行标准，不是梗概，不被压缩。
- 关联角色、场景、道具均来自真实描述。
- 用户可见分集编号、标题、单集梗概、完整剧本、选择问题、选项文字和结局正文。
- 用户不看到剧本分析、资产字段、是否结局、选项编号和跳转编号。

## 失败处理

- 游戏企划缺失：调用 `outline-generator`。
- `角色描述`、`场景描述`或`道具描述`缺失：调用 `asset-designer`。
- 输出出现未定义字段：把内容归入现有一级或二级字段，不能新增自由字段。
- 编号带字母或前缀：改为纯数字，并同步全部前后节点和互动跳转。
- 前后节点列表与互动节点冲突：以互动关系为唯一来源重新生成前后节点列表。
- 流程图缺节点、缺边或与互动节点不一致：以最终互动节点重新生成流程图；不得根据剧本内容补画或改写跳转。
- 悬疑因果不清、角色动机不明或谜语替代功能信息：回到事实底稿，补齐过去事件、当前触发、主角任务、阻力、规则和证据；为每场重建“问题 → 答案 → 新问题”链条，不靠增加氛围台词修补。
- 同节出现多个核心谜团、旧谜团没有解答或结尾凭空补规则：重建悬念台账；每节只保留一个主要悬念，除最终反转外逐项用既有证据和规则回收。
- 分集剧本像梗概：补足目标、阻力、交锋、信息变化和状态变化。
- 下一集没有回应上一选择、无因换场或梗概先演而剧本从后面续写：返回逐集生产单，补齐每条前置来路的即时后果和开场状态；先在完整剧本中演出承接与转场，再同步单集梗概和本集冲突，不用解释文字掩盖缺戏。
- 台词不像人话：读取真人题材语料，补普通话茬并降低承重句密度。
- 用户看到内部字段：保留下游数据不动，重新整理用户呈现。
- 剧本被放入代码块、表格、引用块、卡片/提示框，或场次、动作、台词被压成单行：保留下游数据不动，改用普通 Markdown 正文、逐行场次格式和自然空行重新排版。

## 安全与生成边界

- 不生成露骨色情、仇恨、违法方法、极端血腥、隐私泄露或真实政治人物宣传。
- 性内容用同意、关系距离、浪漫张力和情感风险表达。
- 暴力、死亡和心理痛苦用结果、悬念、环境、象征或非血腥动作表达。
- 未成年人内容必须符合年龄阶段，禁止性化。
- 用户核心元素不安全时，保留戏剧功能，改成安全替代。

## 触发测试示例

- `使用分集规划师：根据这份游戏企划、角色描述、场景描述和道具描述，生成分集互动结构。`

- `使用分集规划师：给我看每一集的编号、梗概、完整剧本和互动选择。`

## 不应触发的反例

- `帮我从一个脑洞生成游戏企划。` 应使用 `outline-generator`。
- `把游戏企划拆成角色、场景和道具描述。` 应使用 `asset-designer`。
- `根据分集剧本生成分镜和视频提示词。` 应使用下游分镜与视频生成技能。
