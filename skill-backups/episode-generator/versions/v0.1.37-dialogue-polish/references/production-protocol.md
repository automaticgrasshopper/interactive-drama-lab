# 分集轻量生产协议

## 一、规划

1. 读取并冻结上游人物、关系、世界规则、时间地点、道具和结局要求。
2. 写私有情绪脊；未完成不得写因果链。
3. 从情绪脊写私有因果链；未完成不得写分集流程。
4. 把每个因果推进单位直接写成一集：一个流程节点就是一集，不存在节点到分集的二次映射。
5. 写各集梗概。每集只回答：谁想做什么、阻力是什么、这一集实际改变了什么、下一集为何发生。
6. 连接分集选择、反馈、汇合和结局。当前集的每个选项必须直接指向目标分集 ID。
7. 用确定性检查确认每个流程节点都是唯一分集、跳转目标存在、所有结局可达、分支后果不同、互斥路线没有串成连续事实。

情绪坐标与因果链属于私有缓存，不进入公开文件。反俗套和包子原则只用于选择梗概内容，不成为公开字段。

## 二、逐集写作

按观看顺序一次处理一集：

1. 读取当前集梗概、路径内已经发生的事实、正式资产和下一集入口。
2. 按 `lightweight-episode-writing.md` 写完整剧本。
3. 保存正文和本集实际发生的简短事实摘要。
4. 对整集做一次口语化润色，直接替换初稿。
5. 保存当前集为“已口语化”，再处理下一集。

第一集口语化后的去空白可见字符数写入私有长度基准。后续每集必须保持其 90%—110%，每场不少于 350；长度不合格只重做当前集写作，不新增语义审稿层。

写作和口语化是两个简单动作。不要插入生产卡展开、机械字数配额、场面事实审稿、逐句评分、隔离观众、冻结宣告或状态解释。

## 三、事实连续性

全部集完成后，把每条观看路径上的剧本按顺序交给 `continuity-only-review.md`：

1. 只登记可以指出前后证据的事实矛盾。
2. 修复最早造成矛盾的位置，或在后文确有遗漏时修后文。
3. 修复不得改变无关台词、戏剧强度、选择或结局。
4. 重新检查受影响路径；问题为空后记录“事实一致”。

## 四、中断恢复

每集保存正文指纹与状态。恢复时：

- `待写作`：从该集写作开始。
- `已写作`：从该集整场口语化开始。
- `已口语化`：跳到下一集。
- 全部已口语化但未“事实一致”：从全剧事实检查开始。

不得重做正文未变化且已经完成的步骤。

## 五、公开组装

全剧事实一致后才组装各集梗概、分集流程图和完整剧本。内部事实摘要、修复记录和处理状态不得进入公开文件。
