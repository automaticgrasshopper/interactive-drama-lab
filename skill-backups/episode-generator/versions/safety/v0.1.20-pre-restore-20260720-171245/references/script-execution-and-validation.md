# 剧本执行与逐集校验规范

根据冻结生产卡写完整剧本时读取；不参与第一轮拓扑设计。

## 一、规则优先级

发生冲突时按以下顺序处理：

```text
事实与人物认知成立
> 已建立关系与个人得失驱动反应
> 场景完整自然
> 生产卡结果与边界得到执行
> 人物对白自然且可理解
> 制片格式正确
```

低优先级不得破坏高优先级。生产卡冻结的是入口事实、核心结果、路径状态和出口，不冻结每一个动作、反应与句子。写核心场面前读取相关人物的当前情感得失、关系状态和未解决心结，让它们决定反应顺序；不从定性体验或数值倒推动作。结构、前史、权限或人物关系有问题时返回生产卡，不用台词或旁白弥补结构缺口。

正式写正文前读取 `screenplay-forging-bridge.md`，在当前生产卡内完成写作护栏和场级施工图。它只把冻结节点转成完整场面，不改变拓扑、路径状态和九字段接口。

## 二、先写连续戏

不要直接对着动作与台词模板逐行填充。根据场面本身选择事件驱动或对抗驱动的连续因果。

事件驱动场面：

```text
正常状态
→ 事件发生并被人物感知
→ 人物依据认知、关系和个人得失作出自然反应
→ 旁人按自己所知解释或处置
→ 产生现实后果
→ 人物采取下一步行动
```

对抗驱动场面只在双方目标真实相冲时使用：

```text
人物为当前目标采取行动
→ 对方基于自身目标阻挡或回应
→ 动作和台词迫使下一次反应
→ 信息、关系、权力、目标或风险发生变化
→ 本场结果推动下一场
```

一场戏只要完整演出事件、反应、结果，并改变后续行动，就完成了戏剧任务。不要求每个角色都有独立目标，不强制冲突、关系变化、权力翻转或选择。只有一个动作和一句反应且没有结果时，应与相邻内容合并或继续展开。

核心关系或个人创伤被触发时，先写人物对失去、重逢、背叛、保护或羞耻的本能行动，再让他处理任务。关系不是一句称谓或背景字段；它必须改变说话顺序、身体反应或行动优先级。普通过场和程序角色不强制扩大情感。

新人物首次出现时自然交代出场动作、身份锚和来意。场景首次使用时说明人物为何进入；道具首次出现时交代原位置、发现者或取得过程。

## 三、关键情节与题材辨识

承担互动、反转、高潮或分集落点的关键情节必须同时具备：

1. 可见、可信、可拍摄的具体事件；
2. 只在当前题材和既有规则下成立的反差物；
3. 由人物行动造成的规则内升级；
4. 能推动下一场或下一集的结果、问题或选择。

关键反转必须来自“既有铺陈触发行动，行动造成反差结果”的连续因果。不得用无关突发事故、临时新增规则或新人物替代反转。

第一集应先建立主角的正常处境和做事方式，再让异常具体发生；让观众看懂主角为何在场、为何反应和接下来准备做什么。主要关系只需在它自然参与事件时登场。

## 四、中文对白

具体对白以 `chinese-dialogue-craft.md` 为准。写作时执行：

- 普通搭话、确认、追问、拒绝、回避、复述、迟疑和反应占多数；
- 承重句只放在举证、揭露、关系变化、规则说明、条件和决定处，不超过一场台词的三分之一；
- 连续三句都在发布背景、规则、秘密或结论时，改为可见动作、普通反应或真正存在目标阻力的来回；
- 每句重要台词都回应前一个动作、台词或眼前事件，并推动当场处置或下一行动；
- 不同人物依据身份、关系、欲望和声音气质形成不同说话方式；
- 悬疑、古装、危险关系和奇幻题材不等于短句、机锋、难以理解的隐喻或口号式表达的堆叠；
- 功能信息必须一遍听懂，悬念只保留具体问题的答案。

## 五、真人样例对照

每集初稿完成后先读取：

- `chinese-dialogue-craft.md` 中与当前题材或关系最接近的素人短剧片段；

再按场面类型有条件读取：

- 只有外部问题的解决方式会反噬人物关系时，读取《权势解围与关系反噬》；
- 只有谈判、审讯、威胁、举证或条件逐级加码时，读取 `gold-sample-episode.md` 中《刘熙的条件》；
- 发现、日常连接、独处反应和纯事件驱动场面，不为贴合样例改造成对抗。

校验只使用以上语料，禁止临时生成 AI 示例句。只比较方法，不复制台词和情节。

对照素人语料检查：

- 人物是否围绕眼前具体事情说话；
- 是否存在来意、拒绝、追问、劝说、改口和反应；
- 熟人、陌生人、上下级和对手的口气是否不同；
- 是否像真实中文交流，而不是轮流吐露资料。

对照《权势解围与关系反噬》检查：

- 人物是否因现实利益接受或拒绝帮助；
- 外部冲突的解决办法是否反过来改变关系；
- 前段表达的价值观是否被后段人物行动实际检验；
- 场景结束后是否留下必须承接的关系后果。

对照《刘熙的条件》检查：

- 每个人当下目标是否明确；
- 对方抵挡后才亮出约束力更强的证据，而非一次性集中说明全部背景；
- 证据是否改变权力和行为；
- 互动是否从具体条件与代价中自然产生。

## 六、逐集四层验收

每集写完后先保存完整初稿，再按固定职责执行四层验收。不得增加平行门禁，不得让同一问题在多层重复争夺裁决权。

```text
场面事实层
→ 人物交流层
→ 隔离观众层
→ 机械冻结层
```

冲突时统一使用：`上游事实与普通现实 > 观众能看懂眼前现状 > 人物认知与关系 > 事件完整发生 > 对白自然 > 戏剧技巧 > 篇幅与格式`。低优先级不得迫使高优先级改坏；机械指标失败时返回场景执行层补足真实事件、反应和结果，不添加解释性台词或无状态作用的动作。

### 语义触发登记

写正文前在当前分集缓存登记以下五项，生产卡修订前不得事后改成`无`来规避检查：

```text
- 首次出现人物：无/角色名@场N
- 核心关系触发：无/人物A↔人物B@场N
- 关键事件：事件简述@场N
- 关键干预：无/栽赃、偷换、潜入、举证等@场N
- 互动选择：无/选择问题@场N
```

每项由唯一层级负责：首次出现、关键事件和关键干预归场面事实层；核心关系和对白归人物交流层；隔离观众层只判断正文是否让观众看懂，不读取触发登记答案。

### 第一层：场面事实复核

当前主 Agent 只读取入口硬状态、直接前置真实结尾、当前生产卡、语义触发登记、当前正文和直接后续进入条件，检查：

- 首次出现人物是否通过出场动作、可见身份锚和当前来意进入场面；称谓本身不能代替来意和身份功能。
- 事件是否先发生并由具体人物以可见或可闻方式感知，再出现第一反应、对白和下一行动；倒叙或延迟揭示只有在观众仍能看懂当前现状时成立。
- 地点、权限、知情、证据和道具是否有来源；关键干预是否有接触机会、移动路径和发现方式。
- 人物行动是否遭遇人物、环境、程序、信息或风险阻力，并形成调整、可见结果和后续入口。

每项依据必须写成`PASS｜场次｜正文中的具体动作或台词及其因果作用`。场次必须真实存在于当前正文；不能写“整体成立”“符合设定”或只复述生产卡。

### 第二层：人物交流复核

清理第一层的事实检查上下文，只读取当前正文、人物身份与关系、语义触发登记中的核心关系项和 `chinese-dialogue-craft.md`，检查：

- 是否严格抽取了正式场次内全部真实台词，并排除梗概、出场、选择和审计文字。
- 逐句润色后是否按原场次、原说话人和原顺序写回；只改台词时动作行必须逐字不变。
- 姓名知情、信息权限、关系距离和上下句承接是否按正文时间成立。
- 人物声音是否来自身份、利益与防御方式；不得替作者总结人物、主题、选项或下一集钩子。

每项依据使用`PASS｜场次｜“正文真实台词”及其作用`。引号内台词必须逐字存在于当前定稿；四项证据合计覆盖全部对白场次，不得引用梗概、选项或动作冒充台词。

### 第三层：隔离观众复核

按 `per-episode-memory-and-cold-read.md` 执行。输入只能包含当前路径下观众实际看过的摘要和当前正文；不得提供入口硬状态、生产卡、语义触发登记、人物秘密、作者计划、后续答案或预期结论。独立读者只判不改；无法取得独立上下文时标记`隔离方式：最小上下文复检`，并重新只读取上述两项。

### 第四层：机械冻结

机械脚本只检查它能够确定的内容：格式、字符与动作段、拓扑和资产名称、记录栏目、正文 SHA-256、证据所指场次是否存在、未解决问题是否为`无`、汇总稿是否来自冻结定稿。脚本不得声称已经判断人物自然、关系成立、事件因果或对白可说，也不得自行生成语义 PASS。

任一正文修改都会使三层记录的旧正文指纹失效；完整复核、保全确认和依赖范围只按主`SKILL.md`的修改分类矩阵执行。一次定点修复仍失败时返回生产卡，不继续叠加补丁。PASS 后生成本集六十至一百字观众摘要。

### 机械完整度检查

默认中篇互动影视剧本的每个节点必须达到：

- 私有缓存中当前集定稿去除空白后的可见字符数为 850—1300；
- 以独立 `△` 行计数的动作段为 16—24 段；
- 私有缓存同时保存真实初稿、真实定稿和本次度量记录。

这组范围用于阻止梗概式压缩，不要求仅为达到字数增加内容。若上游明确指定单集时长或体量，先按指定体量换算并在 manifest 记录本项目门槛；未明确指定时不得自行降低。结局、失败小结局和纯选择节点也按默认门槛执行，除非上游明确要求短结局。

初稿任一项不达标时，先返回场景执行层，不进入三层语义复核；必要时把信息发现、人物理解、反应、调整和结果充分演出，但不得添加不改变人物认知、关系、风险或行动的填充动作。三层通过后，机械冻结层对同一指标重新计算；这是同一机械职责的写前预检和最终复算，不是两道不同门禁。

三层语义记录必须同时指向当前候选正文去除首尾空白后的同一 SHA-256，且未解决问题均为`无`。场面事实采用完整复核或保全确认；保全条件、动作骨架指纹和记录格式见主`SKILL.md`与`canvas-cache-protocol.md`。

## 七、自动修复

任一语义层失败时，只解冻当前集的失败场次，并按问题归属修复：

- 删除重复解释和无行动作用的台词；
- 把说明改为可见事件、普通反应，或确实存在的劝阻、交换、掩饰、举证、逼问和自保；
- 把长独白拆成动作与短反应；只有真实对抗场面才拆成有抵抗的多轮来回；
- 保留必要承重句，其余改为普通接话和反应；
- 把承担多个戏剧任务的不自然表达改为当下最直接的请求、回答、拒绝或追问；可以删除时直接删除，不用另一句修辞性表达替换；
- 修正人物、场景、道具与前置状态的不连续；
- 删除仅为满足模板而添加、却不改变结果的冲突和角色功能；
- 补足核心事件中人物辨认意义、情感冲动和行动选择之间缺失的一步，不用解释关系的台词替代；
- 补演选择行为、即时结果或必要转场。

若失败来自人物权限、关键证据来源、世界规则或核心因果，不得用新增对白修补，直接返回生产卡。修复后按主修改矩阵执行完整复核或保全确认，任何旧正文指纹都不得直接沿用。隔离观众一次修复仍失败，或前两层连续两次仍失败时，检查生产卡是否不可执行；生产卡有问题则返回第一阶段修订受影响节点及其依赖范围。

只有三层语义复核和机械冻结条件全部通过，且记录指纹与当前正文一致，当前集才可冻结、生成观众摘要并回写真实结尾状态。定稿脚本只能验证已有记录的结构、场次定位和一致性，不能自行填写或解释语义 PASS。

## 八、制片格式

校验通过后使用普通 Markdown 逐行排版：

```text
# 第N集《标题》

单集梗概：本集梗概。

【场一 · 地点 · 日/夜 · 内/外】
出场：人物

△ 可拍摄的动作或环境变化。

人物：台词
```

Canvas 正文不使用代码块、表格、引用块或卡片。动作只写可拍内容，可承载连续动作；场与场之间由前场结果、问题或目标推动。

定稿中不保留“扩展场面”“收束场面”“补充场面”“加写”“返工”“优化后”“润色版”等修订标签。为通过完整度门禁补入的内容必须融入现有正式场次，或以包含地点、时间和内外景的标准场次标题新建场次；不得用粗体、Markdown 标题或说明词包装追加段落。
