# 分集规划师

当前规范版本：`v0.1.20`；新建项目缓存版本：`episode-cache-v0.1.20`。

## 单一主任务约束

全部规划、写作、修复和文件更新必须由当前主 Agent 在同一个任务中顺序完成。场面事实复核和人物交流复核仍是当前主 Agent 清理上下文后的两次顺序检查，不得委派。唯一例外是逐集隔离观众复核：候选正文完成前两层复核后，可以调用一个不继承写作历史、只读路径内观众摘要和当前正文的独立读者；读者只判不改，生成方负责返修和文件更新。不得用隔离读者扩大写作并行度或拆分拓扑生产。

## 主要职责

把已确认的游戏企划和角色、场景、道具描述，生成供公开阅读、互动程序执行和下游分镜继续使用的完整分集互动剧本。

负责回答：

- 故事分成哪些节点，节点之间如何推进、分支和汇合。
- 每一集发生什么，人物关系、信息、权力和情绪如何变化。
- 玩家在哪里选择，每个选择立即造成什么结果并通向哪里。
- 每一集如何承接前集、形成钩子并进入后集。
- 每一集如何写成有动作、有来回、有自然中文台词的完整剧本。
- 全局人物、道具、证据、悬念和情绪状态如何保持一致。

不要生成新的游戏企划、角色描述、场景描述或道具描述，不要生成分镜、镜头、图像提示词、视频提示词或媒体。

## 输入要求

这是 `episode-generator` 自己必须读取的唯一输入契约。必须收到且只按以下四个一级字段识别：

- `游戏企划`
- `角色描述`
- `场景描述`
- `道具描述`

只有名称或标识、没有实际描述时，视为输入缺失。四项缺少任一项、使用其它字段名代替或无法读取实际描述时，不创建 Canvas、不创建项目缓存、不开始规划。不得把本 Skill 交给故事版的九个输出字段当成本 Skill 输入。四项通过后，按原字段名和原顺序写入私有 `input.md`，确定性校验仍不通过时停止生产。

会改变玩家身份、核心目标、人物关系、世界规则、关键道具来源、分支或结局的冲突必须先解决；次要缺口不阻塞生产，但不得自行添加新设定。

上游可以传入全部子字段。本 Skill 按阶段读取所需字段，原始资料始终保留为事实源。

## 固定产物

### 公开成果

全部流程完成后写入 Canvas：

1. 分集流程图。
2. 全部分集编号、标题、单集梗概和玩家可见选项。
3. 全部完整剧本和结局正文。

流程图和梗概是写入 Canvas 的中间产物，不作为阶段性消息，不询问是否确认或继续。输入明确限定为结构、流程图或部分分集时，才按指定范围提前结束。

### 画布公开层

向当前 Canvas 项目写入并长期保留：

- `episode-structure.md`：流程图、节点梗概和玩家可见选项。
- `episode-flowchart.svg`：从冻结拓扑确定性生成的静态流程图，供不支持 Mermaid 的页面直接显示。
- `episode-script.md`：由私有缓存中已冻结的逐集定稿按编号自动组装的玩家可见最终稿。

玩家可见层不创建 `episodes/`、`episode-delivery.md`或任何交接文件。逐集初稿、定稿、复核记录和九字段来源只保留在 Canvas 外私有缓存；收到单集修改请求时，修改对应私有分集定稿，再依据影响范围更新直接后续节点和 `episode-script.md`。

### 交付故事版的锁定输出契约

这是 `episode-generator` 完成后交给故事版/分镜模块的输出契约，不是本 Skill 的输入接口，也不是内部缓存结构。

每一集按以下顺序输出：

1. `分集编号`
2. `分集标题`
3. `分集剧本`
4. `剧本分析`
5. `关联角色`
6. `关联场景`
7. `关联道具`
8. `是否结局`
9. `互动节点`

`分集剧本`固定包含：

1. `单集梗概`
2. `完整剧本`

`剧本分析`固定包含：

1. `本集冲突`
2. `前置节点编号列表`
3. `后续节点编号列表`

`互动节点`固定包含：

1. `是否为分支节点`
2. `是否有选择问题`
3. `选择问题`
4. `选项列表`
5. `默认下一分集编号`

`选项列表`中的每一项固定包含：

1. `选项编号`
2. `选项文字`
3. `目标分集编号`

关联资产字段要求：

- `关联角色`、`关联场景`、`关联道具`必须使用上游正式名称或唯一标识，不得写简称、状态描述、“或”关系或临时概括。

故事版按同名字段逐项接收。多集时重复以上九个一级字段，不增加 `分集列表`、文件路径、包装对象或其它一级字段。

内部缓存可以保存生产卡、状态和复核记录，但这些内部字段不得作为故事版输入，也不得改变九字段接口。`scripts/finalize_episode_artifacts.py` 只在内存中组装一次候选字段并执行完整性校验，不创建下游 JSON、交接文件或路径。全部分集通过真实复核并冻结后，当前 Agent 才能按上述契约输出；任何分集未冻结时都不得交付。校验器必须拒绝改名、缺字段、多字段、错误嵌套、非上游资产名称以及与当前定稿或拓扑不一致的传参。

## 画布与缓存

### 工具

使用以下工具完成持久化生产：

- `ls`：查看目录直接子项并确认父目录；递归定位使用 `glob`。
- `glob`：匹配 Canvas、缓存和分集文件路径，不搜索文件内容。
- `read_file`：读取原始资料、缓存和滚动窗口；大文件使用 `offset / limit` 分页，编辑前先读取目标文件。
- `write_file`：只创建不存在的公开文件和缓存文件；写入前确认父目录存在，已有文件改用 `edit_file`。
- `edit_file`：在已读取的文件中执行精确字符串替换，`old_string` 必须唯一且包含足够上下文。
- `grep`：按字面字符串搜索内容并用 glob 限定范围，检查人物、道具、规则、钩子和隐藏字段的跨集引用。
- `exec`：创建缓存目录并运行 DAG、编号、缓存完整性和页面构建等确定性校验；文件查找和读取优先使用上述专用工具。
- `skill_load`：先加载主说明，再按阶段通过 `path` 加载 supporting files，避免同时占用上下文。
- `ask_user`：只在必需输入缺失、主线级冲突无法唯一解释或缓存无法恢复时请求最小必要信息；不询问 Canvas 路径、阶段确认或是否继续。
- `todo`：记录长流程进度，不保存剧情状态。

### Canvas 定位

1. 先用 `ls` 和 `glob` 查找当前 workspace 中的 `**/.episode-generator-cache/*/manifest.md`；以缓存目录名作为项目 slug，核对对应 `canvas/{slug}/episode-structure.md`。
2. 只有一个项目时直接使用。
3. 有多个项目时，依次核对游戏标题 slug、页面标题、任务关联文件和已有 manifest；只有内容匹配的候选才能入选，最近更新时间只用于匹配候选之间的排序。
4. 没有通过内容核验的项目时，使用游戏标题 slug 在当前 workspace 的 `canvas/` 下创建公开项目目录，在 workspace 根目录的 `.episode-generator-cache/{slug}/` 创建私有缓存目录。
5. 将候选、核验结果和最终路径写入 manifest，全程不询问路径选择。

### 缓存目录

在 workspace 根目录创建与 Canvas 分离的私有目录。`write_file` 没有隐藏字段，因此不得把内部文件写进 Canvas 后假定平台会隐藏：

```text
.episode-generator-cache/{slug}/
├── manifest.md
├── global.md
├── topology.md
├── characters.md
├── props.md
├── hooks.md
├── validation.md
└── episodes/
```

使用 `exec` 创建父目录，使用 `write_file` 创建新文件。manifest 必须记录对应 Canvas 绝对路径。缓存目录只保存内部状态，不投射到公开层；Canvas 项目根目录不得出现缓存、审计、生产卡或运行日志。

### 缓存职责

- `manifest.md`：版本、项目、当前阶段、节点数、执行组计划、当前执行组、已完成集数、三层语义复核和机械冻结状态。
- `global.md`：事实基线、世界规则、情绪脊、结局条件和场景固定连接。
- `topology.md`：唯一节点与边、互动类型、选项和目标集。
- `characters.md`：每条路径下人物当前目标、已知信息、关系、权力、代价和弧光阶段。
- `props.md`：关键物件来源、持有人、位置、状态、已知作用和待回收节点。
- `hooks.md`：悬念的抛出、部分回答、最终回收和当前状态。
- `validation.md`：逐集与全剧校验结果、失败位置、修复次数和冻结状态。
- `episodes/episode-NNN.md`：单集生产卡、初稿、修订稿、真实结尾和九字段校验所需来源。

## 主流程

### 唯一权威的阶段状态机

本节唯一决定阶段顺序、字段所有权和修改后的失效范围。其它章节与 reference 只解释执行方法，不得重新定义回退规则；发生冲突时以本节为准。

每个执行组依次经过：`未开始 → 已装载 → 候选正文 → 机械预检通过 → 场面事实通过 → 人物交流通过 → 隔离观众通过 → 机械冻结 → 状态已回写`。禁止跳级；上一组达到`状态已回写`后，下一组才能读取其观众摘要、真实结尾和人物、物件、钩子状态。互动节点与全部即时结果、汇合节点与全部直接来路、最终选择与全部直接结局分别作为不可拆分的原子组；组内任一节点失败，整组不得回写下游状态。

阶段固定为：

| 阶段 | 唯一职责 | 失败回退 |
|---|---|---|
| 0 上游输入 | 冻结游戏企划、角色描述、场景描述、道具描述 | 缺项则不进入分集 |
| 1 全局规划 | 事实基线、候选互动、唯一拓扑、生产卡、执行组计划 | 只修改结构层 |
| 2 执行组装载 | 读取当前原子组及全部可靠入口状态 | 当前组内处理 |
| 3 候选正文 | 写连续戏、登记触发、抽取并原位润色真实台词 | 不进入验收 |
| 4 机械预检 | 只查字数、动作段和格式 | 回场景执行层补真实事件 |
| 5 场面事实 | 查来源、权限、出场、事件链、物件路径和后续入口 | 修动作；新规则退生产卡 |
| 6 人物交流 | 查真实台词、姓名知情、话茬、关系距离和朴素表达 | 只改台词；需改动作则退场面层 |
| 7 隔离观众 | 只用路径摘要与当前正文判断普通观众能否看懂 | 问题归回事实层或交流层 |
| 8 机械冻结 | 核对指纹、证据、资产名、格式和状态顺序 | 只报告机械错误 |
| 9 状态回写 | 生成摘要与真实结尾，更新人物、物件、钩子和组状态 | 当前组保持未提交 |
| 10 全剧校验 | 统一检查轨迹、分支汇合、九字段和公开三文件 | 只解冻受影响节点 |

### 字段所有权

| 内容 | 唯一权威来源 | 下游权限 |
|---|---|---|
| 四项正式输入 | `input.md` | 只读，不改名、删项或重写 |
| 节点、边和选择目标 | `topology.md` | 剧本只兑现，不自行改跳转 |
| 本集必须发生什么 | 生产卡 | 候选正文执行，不重新定义 |
| 本集实际发生什么 | 私有当前定稿 | 状态文件从冻结定稿提取 |
| 人物、物件、钩子当前状态 | 对应状态文件 | 下一组只读已回写状态 |
| 九字段接口 | 锁定输出契约 | 不增删、改名、换序或改嵌套 |
| 公开三文件 | 冻结缓存投射 | 不作为反向编辑源 |

### 修改分类、指纹与失效

正文任何变化都会使三层记录的旧`正文 SHA-256`失效；语义结论只按以下影响范围完整重审。所有层在再次冻结前都必须绑定当前正文；未完整重审的上游层只能经过规定的`保全确认`重新绑定，不能只替换 SHA。

| 修改类型 | 场面事实 | 人物交流 | 隔离观众 | 依赖范围 |
|---|---|---|---|---|
| 表层台词润色 | 保全确认 | 完整复核 | 完整复核 | 当前集 |
| 台词改变姓名、事实、条件或决定 | 完整复核 | 完整复核 | 完整复核 | 按事实影响计算 |
| 动作或场次修改 | 完整复核 | 完整复核 | 完整复核 | 当前集与必要直接后续 |
| 真实结尾修改 | 完整复核 | 完整复核 | 完整复核 | 所有依赖节点 |
| 拓扑或正式输入修改 | 返回阶段 0/1 | 后续失效 | 后续失效 | 重算拓扑依赖 |

`保全确认`只允许表层台词润色：上一冻结定稿必须保留，场次、出场、动作、选择和非台词文字组成的动作骨架指纹必须逐字相同；姓名、事实、条件、决定、物件来源和出口信息不得改变。机械脚本只验证上一冻结正文、动作骨架和记录结构；事实含义仍由当前主 Agent确认。任一条件不成立，自动升级为场面事实完整复核。

全部流程在一次任务中自动连续执行。中间不发送流程图完成、结构完成、批次完成或校验完成等阶段性消息，也不询问是否继续。全部请求范围完成并通过最终校验后，只发送完成状态、校验结论和 Canvas 入口；完整内容保留在 Canvas。

### 可见进度

默认不发送中间消息；环境强制要求时，只说“正在处理，完成后统一交付”。不展示内部分析、状态、文件或执行步骤；需要用户补充输入时，只说明缺少什么。

### 第一阶段：全局规划并落画布

1. 读取 `references/production-protocol.md`、`references/canvas-cache-protocol.md` 和 `references/emotional-spine-and-branching.md`；悬疑、惊悚、犯罪、反转、秘密或证据延后揭露题材同时读取 `references/causal-clarity-and-suspense.md`。
2. 通过输入门禁，定位 Canvas，创建缓存目录和清单。
3. 从上游建立事实基线、规则、场景连接、人物初始关系、关键物件来源和结局条件。
4. 从上游内容提取关系目标、核心任务目标和当前情绪，建立主干情绪脊；对命令、请求、交易、威胁、隐瞒、救援、牺牲和不可逆操作执行行动岔口扫描，把玩家拥有多个有效行动的关键决定保持为未决。
5. 建立候选互动表，执行负面可剥离、正面可认领、前五分钟交互和分支遗漏审计；用可执行性、互斥性、即时状态差、代价与 VAD 方向差筛选后，确定节点数、选择功能、拓扑等级、分支、汇合和结局。
6. 拓扑冻结后不再把 PAD/VAD 数值带入内容阶段；依据节点的定性体验功能、入口事实和出口条件，为每集建立生产卡，写明核心事件、人物反应、当前情感得失、事件对人物的意义、结果、关系、信息、场景、物件、钩子和后续进入条件。
7. 将全局事实、候选互动审计、拓扑、人物、物件、钩子和生产卡写入缓存。
8. 运行拓扑、分支遗漏、承接、情绪、题材和梗概自检；失败时在缓存中修改并重检。
9. 自检通过后，将静态 SVG 图片引用、折叠的 Mermaid 源码、全部梗概和玩家可见选项写入 `episode-structure.md`；运行 `python3 {skill-root}/scripts/render_episode_flowchart.py {canvas-root} --title "《游戏标题》分集流程图"` 生成 `episode-flowchart.svg`。
10. 确认静态 SVG 覆盖全部节点和边后立即进入第二阶段，不发送阶段性消息。收到结构修改请求时，解冻受影响节点并重算依赖范围，同时重新生成 SVG。

### 第二阶段：按执行组滚动生成完整剧本

1. 读取 `references/script-execution-and-validation.md`、`references/per-episode-memory-and-cold-read.md` 和 `references/chinese-dialogue-craft.md`；当前组包含谈判、审讯、威胁、举证或由具体条件形成的互动时，再读取 `references/gold-sample-episode.md`。
2. 根据拓扑先划分戏剧执行组，不按固定集数分批：
   - 无选择的连续默认推进段组成线性组，遇到互动、重大反转、汇合或结局前停止；
   - 互动节点与它的全部直接即时结果节点组成互动组；
   - 汇合节点必须同时读取全部直接前置真实结尾及其状态差异；
   - 最终选择与它直接打开的全部结局组成结局组。
3. 每组开始前估算上下文容量，给场面事实、人物交流、隔离观众和自动修复保留余量；超出稳定容量时只在状态稳定边界拆分，不拆开选择与即时结果、铺垫与反转、汇合与来路、最终选择与结局。
4. 当前组只读取：
   - `global.md` 的压缩事实，不读取主干情绪脊、PAD/VAD 数值和力度谱；
   - 组内全部生产卡；
   - 组入口的所有直接前置真实结尾；
   - 组出口的直接后续进入条件；
   - 组内实际人物、场景和道具状态；
   - 核心场面相关人物的当前情感得失、关系状态和未解决心结；
   - 组内相关的未回收钩子。
5. 写正文前登记本集语义触发：首次出现人物、核心关系触发、关键事件、关键干预和互动选择；未触发项明确写`无`。按组内拓扑先写连续戏，再按`chinese-dialogue-craft.md`严格抽取真实台词、逐句润色、原位写回和复检，最后转换为普通 Markdown 制片格式。
6. 完整初稿先写入对应私有分集文件，运行每集 850—1300 个去空白可见字符、16—24 个动作段的机械完整度检查；机械指标只拦截梗概式压缩，不得要求改写已经成立的事实、人物反应或对白。上游明确指定其它单集体量时，将换算门槛写入 manifest 后执行。
7. 按固定职责顺序执行三层语义复核：场面事实层只查来源、权限、首次出场、事件—感知—反应、行动、阻力、结果、物件路径和后续入口；人物交流层只查核心关系对反应顺序的影响、话茬目的、人物声音、现场交流和朴素中文；隔离观众层只用路径内观众摘要和正文判断普通观众能否看懂。每项 PASS 必须指向正文中真实存在的场次并说明可核对证据，不能以整体评价代替。
8. 组级校验检查互动行为是否在全部结果节点兑现、分支差异是否真实、节点的定性体验功能是否由实际事件兑现、各结果的篇幅和力度是否明显失衡。
   互动组与汇合组同时按 `screenplay-forging-bridge.md` 执行分支—汇合双向验收；对白轮按 `chinese-dialogue-craft.md` 追加整场过度压缩复检。
9. 校验失败时只修改失败场次或受影响节点并复检；两次修复仍失败时，检查生产卡并解冻受影响范围。
10. 组内全部节点通过后冻结，回写真实结尾、人物、物件和钩子状态，并从私有逐集定稿重新组装 `episode-script.md`，再自动继续下一执行组。
11. 全部执行组通过后，运行 `python3 {skill-root}/scripts/finalize_episode_artifacts.py {canvas-root} --mode finalize`。脚本只核对机械指标、三层记录结构、正文指纹、证据场次定位和未解决问题，不自行判断语义、不生成语义 PASS；全部记录有效时才冻结并组装 `episode-script.md`。

### 第三阶段：全剧压缩对齐与修复

1. 从缓存生成并检查人物轨迹、道具轨迹、钩子轨迹、定性体验轨迹和下游字段覆盖。
2. 使用 `exec` 运行 `python3 {skill-root}/scripts/validate_episode_cache.py {canvas-root} --require-public`，检查节点、边、可达性、编号和文件完整性；`{skill-root}`为当前 `SKILL.md` 所在目录，人物、物件和钩子仍执行语义检查。
3. 当前主 Agent 在同一任务中顺序执行两个只读复检轮：先按场面事实职责检查人物知情时间、证据连续性、事件顺序和状态边界；再清理事实检查上下文，按人物交流职责检查关系触发、行动优先级、对白现场性和人物声音。两轮之间不创建或调用任何子任务、子线程或其它 Agent。
4. 确认问题来源和依赖范围，只解冻受影响节点及其直接后续进行修复。
5. 修复后重新运行相关逐集校验和全剧校验。
6. 全部通过后更新受影响的私有逐集定稿和 `episode-script.md`，在内存中按锁定契约组装九字段交给下游，最后分别提供流程图、分集大纲和完整剧本入口。

## 第一阶段规划规则

### 情绪脊

- 每集记录情绪起点、变化原因和落点。
- 情绪变化必须由获得、失去、关系变化、信息变化、风险或行动权变化造成。
- 至少有一次由玩家选择促成的有效释放；释放后兑现此前登记的风险或代价。
- 不同结局具有不同结果、代价和情绪落点。

### 选择

- 选项使用“动词＋明确对象”，只写玩家此刻执行的一个动作。
- 大纲中已经写成完成态的决定只代表默认走势；玩家若在决定发生前拥有另一个合理、可执行且代价不同的动作，必须先还原为候选互动。
- 玩家角色即将作恶、受辱、背叛、放弃重要关系或承担不可逆损失时，执行负面剥离检查；翻盘、救人、关系靠近和重大成果执行正面认领检查。
- 每个保留互动同时标记戏剧功能（决策性、情感类、调剂类）和拓扑等级（快速汇合、重大路线、小结局）。
- 调剂选择产生不同即时结果后可较快汇合。
- 重大选择进入结局，或展开至少三个连续差异节点。
- 目标集先演选择行为、人物反应和即时结果，再转入新冲突。

### 生产卡

每张卡至少包含：

- 本集作用与单集梗概
- 本集冲突与前后承接
- 前置和后续节点
- 节点的定性体验功能，不包含 PAD/VAD 数值
- 开场处境、核心事件、人物反应、结果和下一行动
- 核心人物当前最怕失去或最想挽回的对象，以及核心事件对他的意义
- 开场必须先演的前置行为与即时结果
- 本集起因、行动、阻力、结果和钩子
- 开场与结尾的时间、地点、人物位置
- 人物关系、已知信息、风险和权力变化
- 实际使用的角色、场景和道具
- 关键物件来源、持有、使用、代价和结尾状态
- 后续进入条件

“阻力”可以来自环境、程序、信息缺口、风险或真实对立者，不等于每集都要安排人物对抗。生产卡冻结结果和边界，不预写具体走位、逐句反应和对白攻防。

## 第二阶段逐集校验

### 场面事实复核

机械完整度预检通过后，当前主 Agent 先读取入口硬状态、冻结生产卡、语义触发登记、当前正文、直接前置真实结尾和直接后续进入条件，只校验：

- 首次出现人物的出场动作、身份锚和来意；
- 地点、权限、知情、证据和道具来源；
- 事件发生、人物感知、第一反应、行动、阻力、调整和可见结果的顺序；
- 关键干预的接触与移动路径、选择即时结果和后续入口。

### 人物交流复核

场面事实通过后清理该轮上下文，按`chinese-dialogue-craft.md`只抽取正式场次中的真实台词。先润色并原位写回，再按正文顺序检查姓名知情、信息权限、关系距离、上下句承接、人物声音和功能信息。复核证据必须逐字引用当前定稿的真实台词，多场含台词时合计覆盖全部对白场次；梗概、选项、动作和生产卡不得作为台词证据。谈判、审讯、威胁、举证或条件升级场面才读取`gold-sample-episode.md`。

### 隔离观众复核

只读取当前路径内观众摘要和当前正文，不读取入口硬状态、生产卡、触发登记、作者计划或后续答案。按 `per-episode-memory-and-cold-read.md` 判断新人物是否可识别、事件顺序是否可见、关系是否有正文证据、对白是否围绕眼前人事、结果和下一行动是否清楚。

三层不得合并，也不得重复争夺同一问题的裁决权。三份记录必须绑定当前正文并写入真实场次证据；修改后的完整复核、保全确认和依赖范围只按“唯一权威的阶段状态机”执行。

## 单集修改

收到单集修改请求时：

1. 读取对应私有分集缓存的当前定稿、所有直接前置真实结尾和直接后续进入条件；`episode-script.md` 只用于玩家阅读，不作为修改源。
2. 判断修改是否改变该集真实结尾、人物关系、已知信息、物件状态、钩子、分支或结局条件。
3. 不改变边界状态时只修改该集，并按修改分类矩阵执行保全确认或完整复核；不得笼统重跑全部层，也不得直接沿用旧指纹。
4. 改变边界状态时，计算依赖范围，解冻并校验所有受影响的直接后续、引用该事实或物件的节点和相关结局。
5. 校验通过后运行 `finalize --episodes episode-NNN`，由全部已冻结的私有逐集定稿重新组装 `episode-script.md`；不从玩家可见汇总稿中反向拆集，也不整部重新生成。

### 只改台词

用户只要求润色、口语化或修正台词时，以私有当前定稿为底稿并锁定全部动作行：

1. 抽取正式场次内全部`说话人：台词`，排除梗概、出场、选择和审计文字。
2. 只改抽出的台词，按原场次、原说话人和原顺序写回；动作行必须逐字不变。
3. 允许补上相邻问句已经要求的最小回答，例如漏写的自报姓名；不得新增剧情、伤势、前史、物件或关系过程。
4. 写回后依次检查姓名知情、信息权限、关系距离、上下句承接和功能信息。任一项失败只改对应句。
5. 一句话必须改动作才成立时停止并标记`需要场景层修复`；获得场景修改范围后再重跑场面事实层，不得在对白润色中暗改。
6. 人物交流证据逐字引用真实台词并覆盖全部对白场次；之后重跑隔离观众和机械冻结。

## 画布呈现

### 流程结构

`episode-structure.md` 首先使用 `![分集流程图](./episode-flowchart.svg)` 显示静态图；随后把 Mermaid `flowchart` 源码放入折叠的 `<details>`，作为可编辑备份。静态 SVG 与 Mermaid 必须展示全部节点、默认推进、选项边和结局，随后按编号展示每集标题、单集梗概和玩家可见选项。默认在完整剧本与最终校验全部完成后，与完整稿一并写入 Canvas；不单独发送结构完成消息。

不得只交付 Mermaid 代码块。平台不渲染 Mermaid 时，静态 SVG 仍须独立显示完整流程图；SVG 由脚本从 `topology.md` 生成，不手写、不从梗概重新推断。

### 完整剧本

使用普通 Markdown：

```text
# 第N集《标题》

单集梗概：本集梗概。

【场一 · 地点 · 日/夜 · 内/外】
出场：人物

△ 可拍摄动作。

人物：台词
```

Canvas 正文不使用代码块、表格、引用块或卡片。完整稿包含全部分集和全部结局；内部滚动批次不改变交付范围。

正式剧本只使用分集标题、单集梗概、标准场次标题、出场、动作、台词、互动选项和结局正文。不得出现“扩展场面”“收束场面”“补充场面”“加写”“返工”“优化后”“润色版”等修订标签或非制片标题；新增内容必须融入原场，或使用完整的 `【场N · 地点 · 日/夜 · 内/外】` 新建正式场次。

### 完成消息

只报告完成状态和真实校验范围，并分别提供 `episode-flowchart.svg`、`episode-structure.md` 与 `episode-script.md` 三个入口；不再生成或链接 `index.html`。不重复粘贴流程图、梗概、完整剧本、私有缓存或下游参数。输入明确要求在对话中展开具体内容时，才按指定范围展示。

## 验收标准

### 画布与缓存

- Canvas 项目定位唯一，公开层只有流程图、分集大纲和最终完整剧本，逐集文件与交接数据不进入玩家可见层。
- 每个拓扑节点都有一个对应的 Canvas 外私有分集缓存。
- 公开层不包含隐藏分析、情绪数值、生产卡和校验记录。
- 缓存中的全局事实、拓扑、人物、物件、钩子和分集文件完整。
- 汇总稿与私有逐集当前定稿逐字一致，不是重新生成的另一套正文。
- 流程图、大纲和汇总稿来自同一拓扑与同一批冻结正文；不维护第二套 HTML 阅读页。

### 结构

- 第一集是唯一入口，全部节点可达，无循环、孤立和非结局节点缺少后续连接的情况。
- 流程图、选项、生产卡和下游参数来自同一拓扑。
- `episode-structure.md` 引用了静态 SVG，SVG 覆盖全部节点和边；不能以 Mermaid 源码框代替可视流程图。
- 选择分级正确，重大路线具有足够差异节点。
- 候选互动审计覆盖所有关键命令、请求、交易、威胁、隐瞒、救援、牺牲和不可逆操作；不存在编剧替玩家预先完成的关键决定。
- 负面剥离点、正面认领点和前五分钟交互均有保留或删除结论；保留候选已落入拓扑，删除候选具有事实或状态差理由。
- 情绪有压制、释放、反噬、翻盘或明确题材例外，结局落点不同。

### 逐集与执行组

- 执行组按拓扑中的完整戏剧单元划分，不按固定集数划分。
- 互动节点与全部即时结果同组，最终选择与全部直接结局同组；汇合组读取全部来路。
- 每组开始前已估算容量，并为场面事实、人物交流、隔离观众和自动修复保留余量。
- 每集执行冻结生产卡，前后状态连续。
- 每集默认达到 850—1300 个去空白可见字符和 16—24 个动作段；私有缓存保存真实初稿、真实定稿与度量记录，占位文字不能通过校验。
- 每集场面事实、人物交流和隔离观众均有指向当前定稿 SHA-256 的具体复核记录；每项依据均定位到当前正文真实场次。记录缺失、泛写、场次不存在、仍有未解决问题或正文指纹变化时不得冻结。组级互动、分支和定性体验校验通过。
- 每集定稿不含扩展、收束、补充、返工、优化或润色等修订标签，所有标题都是规定的制片结构。
- 中文对白先严格抽取、只润色、原位写回，再复检姓名知情、信息权限、关系距离和功能完整；对白证据必须逐字来自真实台词并覆盖全部对白场次。
- 规则、证据、物件来源和代价通过动作或台词让观众看懂。
- 钩子有后续回答，人物与道具状态已回写缓存。

### 全剧

- 人物知情、关系、弧光和权力变化无冲突。
- 道具与证据来源、持有、状态和回收完整。
- 各节点的定性体验功能在实际剧本中由事件兑现，不把情绪数值带入正文执行。
- 下游参数与剧本事实一致。
- Canvas 完整稿包含全部节点和结局。

## 失败处理

- Canvas 存在多个候选：先验证标题 slug、页面标题、任务关联文件和 manifest，只在匹配候选中使用最近更新时间排序；没有匹配项时创建新项目。
- Canvas 不存在：在当前 workspace 的 `canvas/` 下创建以游戏标题 slug 命名的项目。
- 缓存父目录不存在：使用 `exec` 创建后再写文件。
- 上游事实存在冲突：按明确指令优先、正式字段优先、具体描述优先于概括描述的顺序统一；仍有多种会改变主线的有效解释时使用 `ask_user` 请求最小必要澄清，次要歧义采用对核心目标和既有资产改动最小的解释并写入私有缓存。
- 缓存无法恢复：先核对 manifest、拓扑和实际文件；仍无法唯一判断可信状态时使用 `ask_user`，不得猜测或覆盖已冻结正文。
- 结构或情绪失败：返回全局规划和受影响生产卡。
- 中文对白失败：只改失败场次，复检后再冻结。
- 因果或连续性失败：先修正事实链、当前集或前置真实结尾；若涉及新规则、权限或关键证据则返回生产卡，并更新依赖节点。
- 全剧校验发现冲突：按依赖范围定点修复，不整部重新生成。
- 工具或画布暂时不可用：不得声称已写入画布；改为输出可恢复的缓存文件并说明实际状态。

## 边界

- 不把缓存内容投射到公开页面或完成消息。
- 场面事实、人物交流复核与全部修复始终由当前主 Agent 在同一任务中顺序完成；仅逐集隔离观众复核可调用只判不改的独立读者，且不得委派写作或文件更新。
