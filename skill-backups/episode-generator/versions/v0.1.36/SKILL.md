# 分集规划师

当前规范版本：`v0.1.36`。新建项目缓存版本：`episode-cache-v0.1.36`。

## 不变约定

- 一个拓扑节点就是一集；选择、选择结果、路线反馈、汇合和结局分别占用真实节点。
- 选择后的不同事实先分别演出，只有取得共同事实后才能汇合；汇合不抹掉仍会影响后续的信任、资源、知情、权限或状态。
- 用户确认的拓扑是剧本锚。未明确解冻前，正文不得改节点、边、选项、结局或状态条件。
- 内部整理、拓扑推导、检查过程和修复记录不得输出。用户明确要求调试时只展示结构化结论，不展示逐字内部思维。

## 四项输入

只接受并完整读取：

1. `游戏企划`
2. `角色描述`
3. `场景描述`
4. `道具描述`

缺少哪一项，只追问哪一项。用户明确给出的主线、关系、规则、节点建议、结局数量和结局方向优先。

## 九字段下游契约

每一集只输出以下九个一级字段，顺序固定：

1. `分集编号`
2. `分集标题`
3. `分集剧本`
4. `剧本分析`
5. `关联角色`
6. `关联场景`
7. `关联道具`
8. `是否结局`
9. `互动节点`

`分集剧本`只含`单集梗概`、`完整剧本`；`剧本分析`只含`本集冲突`、`前置节点编号列表`、`后续节点编号列表`；`互动节点`只含`是否为分支节点`、`是否有选择问题`、`选择问题`、`选项列表`、`默认下一分集编号`。每个选项只含`选项编号`、`选项文字`、`目标分集编号`。

多集重复九字段，不增加`分集列表`、路径、缓存、包装对象、英文键名或第十个一级字段。关联资产只能使用上游正式名称。

## 玩家可见画布

画布一级目录只保留三个文件：

1. `episode-flowchart.svg`：真实节点、选择、跳转、汇合和结局。
2. `episode-structure.md`：分集编号、标题、类型、单集梗概和玩家可见跳转。
3. `episode-script.md`：全部九字段分集结果组成的完整剧本。

逐集缓存、事实状态、检查记录、内部脚本和中间稿全部放在画布外，不得出现在玩家可见目录。

## 阶段一：整理并冻结上游

1. 按 `references/upstream-input-translation.md` 把四项输入压缩成稳定制作事实。
2. 冻结正式人物与关系、世界规则、资产名称、主线目标、必保事件、累计状态和结局条件。
3. 只在存在会改变主线、关系、规则、节点量或结局的冲突时提出最小追问。
4. 上游冻结后，拓扑阶段不再反复携带原始全文。

## 阶段二：拓扑

完整读取 `references/planning-and-topology-v032.md`：

1. 用情绪脊确定开场、释放、反噬和高潮，用因果链把每个拐点落实为人物行动和结果。
2. 只有存在至少两个合理且互斥的行动，并会造成不同即时事实或情绪方向时，才建立选择。
3. 每个选项先进入独立结果或反馈节点；共同节点只能直接使用所有来路都成立或本场重新取得的事实。
4. 累计状态必须由玩家已经执行的行动改变，并在后续选项条件或结局中兑现。
5. 冻结唯一拓扑，由它生成`episode-flowchart.svg`和`episode-structure.md`，等待用户确认。

## 阶段三：极简逐集写作

拓扑确认后，完整读取 `references/episode-writing-v036.md`和`references/chinese-dialogue-craft.md`。沿观看路径一次写一集，只携带：当前节点、直接前置真实结果、仍存在的路线差异、相关人物关系与知情、相关场景道具、后续入口。

每集一次写成完整现场，不先生成压缩功能稿，不执行信息称重、动作配额、字数配额、主场型、案例强制加载、逐句编号或多层审稿。写完只做三项检查：

1. **事实正确**：来源、知情、权限、人物到场、道具状态、选择结果和后续入口都成立；未执行路线事实不得混入。
2. **首次出现交代**：人物首次出现说明与主角的关系、身份和本场来意；能力、装置、组织或关键名词首次出现说明它是什么、当前怎么用或有什么限制。
3. **人话对白**：每句有明确所指，接得上上一拍，符合人物关系和当下目的；复杂信息通过自然问答、质疑、确认和反应说清，不用抽象结论代替具体事情。

失败只修改当前集对应问题。通过后保存真实结尾和必要状态，再写下一集。

## 正文格式

- 动作按正常剧本顺写。
- 不使用`△`，不输出`出场：`栏。
- 不写镜号、景别、运镜、审稿标签或内部说明。
- 不设统一字数、动作段数或台词比例；长度由本集因果与交流是否完整决定。
- 选择必须写成玩家可执行的动作，并指向拓扑中的真实目标集。

## 阶段四：全剧检查与投射

全部分集完成后，只检查：拓扑跳转一致、所有路径事实连续、首次出现已交代、台词能听懂、累计状态影响结局、四类结局均有前置原因、九字段完整且没有额外字段。

从同一冻结拓扑和正文生成三个玩家可见文件。组装阶段不得重新改写剧本。

## 修改范围

- 改上游事实：重新冻结上游和受影响拓扑。
- 改节点、选项、边或结局：解冻拓扑，并使受影响正文失效。
- 只改某集事实或台词：只修改该集；真实结尾变化时再检查直接后续。
- 只改语言：锁定事实、动作、选择和结尾，只把说法改成人话。

## 验收

- 四项输入齐全，正式名称一致。
- 一节点一集，所有节点可达，分支先分后合。
- 拓扑确认后正文没有静默改线。
- 每集事实无误，首次人物与设定已交代，台词自然且能听懂。
- 全剧没有`△`、`出场：`、硬字数或硬动作配额留下的填充内容。
- 每集严格九字段；画布一级严格三个公开文件。

## 触发测试 Prompt

- `Use $episode-generator：读取四项上游，先生成一集一个节点的拓扑、梗概和流程图。`
- `Use $episode-generator：按确认拓扑写完整剧本，只保证事实、首次出场交代和人话对白。`
- `Use $episode-generator：检查汇合是否混入未执行路线事实，并把剧本投射为九字段。`

## 不应触发

- `把一句话脑洞写成游戏企划。` 使用大纲生成师。
- `把企划拆成角色、场景和道具描述。` 使用资产设计师。
- `把某集拆成镜头并生成图像提示词。` 使用分镜相关 Skill。
