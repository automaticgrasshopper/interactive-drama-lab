# v0.1.35 单集场面铺实与验收

本文件只在拓扑确认后读取。一次任务只处理一集的一个问题；当前集未冻结，不得开始下一集。

每集固定领取五个串行任务：`写作包与主场型 → 整场铺实 → 事实复核 → 人物交流复核 → 冻结保存`。同一时刻只允许一个任务处于进行中；铺实任务不得自判通过，复核任务不得改正文，修复任务只处理已登记问题。

## 1. 最小写作包

当前集只读取：

- 拓扑锚版本、节点字段和直接后续进入条件；
- 当前路径事实摘要、直接前置真实结尾和仍存分支差异；
- 当前集入口、必保事实、核心变化和出口；
- 当前集实际使用的角色、关系、场景、道具和世界规则；
- 人物此刻分别想做什么、怎样回避或抵挡、什么不能直接说破；
- 本集表达模式：`台词主导`或`动作主导`；
- 尚未回收且本集会触发的钩子。

禁止读取原始上游全文、情绪数值、淘汰候选、其它路线正文、未来结局正文和已冻结前集全文。汇合集只读各来路的共同事实与仍存差异。

## 2. 主场型选择

每集只选一个主场型；没有匹配时写`普通事件场`，不加载案例。

- `confrontation`：谈判、审讯、揭露、威胁、举证升级或条件逼选。
- `power-reversal`：多人冲突、借权势解围、外部问题解决却反噬关系。
- `evidence-verification`：医疗、调查、技术或异常判断需要现场证据使他人改变态度。

场型只指导信息与反应顺序，不复制案例的人物、台词、情节或时代背景。多个场型都像时，选择决定本集核心变化的一个，不叠加案例。

## 3. 整场铺实

直接写完整场面，不先写压缩功能稿，不把对白抽出后全场重写。按当前事件自然完成需要的环节：

```text
事情发生
→ 人物感知
→ 第一反应
→ 采取具体行动
→ 遭遇人物、环境、程序或信息阻力
→ 调整、举证或核验
→ 现场出现可见结果
→ 关键人物对结果作出反应
→ 形成下一行动或互动选择
```

不要求每场都有争吵，也不要求九步机械齐全。重要判断必须有可见、可闻、可触碰或可核验的现场依据；重要行动必须得到人物、环境或系统回应。关系通过注意顺序、称呼、回避、阻拦、让步和行动优先级进入场面，不用台词总结主题。

允许补普通连接动作和既有物件的正常使用；禁止新增世界规则、关键证据、特殊权限、固定角色、关系前史和巧合救援。选择集必须让现实困境先成立，再出现选项；结果集开场立即演出所选行动和即时结果；汇合集保留各来路尚未消失的差异。

## 4. 台词与动作分工

两人以上围绕关系、条件、选择、判断或利益持续交流时，默认使用`台词主导`；独处发现、追逐、搏斗、蒙太奇和纯异常展示可以使用`动作主导`。

`台词主导`场中，人物的判断、请求、拒绝、追问、证据解释、关系攻防、条件和决定必须由人物说出并得到回应；动作只负责位置、接触、阻拦、物证、核验和可见结果。台词承载的有效信息和篇幅原则上多于动作说明。若动作明显更多，先把动作中代替人物表达的态度、判断和关系意义还给对话，不为比例添加闲聊、复述和空台词。

`动作主导`场不强行增加说话人；但只要现场存在可以回应的人、系统或记录，关键功能信息仍应被说出或播放，不能全部依赖动作说明和观众猜测。

## 5. 事实复核

只读取当前写作包和当前正文，检查必保事实、证据与权限来源、行动回应、可见结果和真实出口。事实通过后锁定场次、动作、事件顺序、选择和结尾状态；失败只返回具体缺口。修复必须改变入口、核心结果或出口时返回写作包。

## 6. 人物交流复核

事实通过后完整读取 `chinese-dialogue-craft.md`，并在同一轮按主场型最多加载一张案例卡：

- `confrontation` → `case-confrontation-liuxi.md`
- `power-reversal` → `case-power-reversal-minguo.md`
- `evidence-verification` → `case-evidence-verification.md`
- `普通事件场` → 不加载案例

普通事件场不加载案例。案例只检查信息攻防和递进，不复制措辞、人物或情节。

先运行 `scripts/prepare_dialogue_review.py <当前正文>`，取得全部真实台词的稳定编号、正文指纹、台词包指纹、台词总数和 `COMPLETE`。逐句检查名词与指代是否已有来源、是否回应或被识别为回避、是否只承担一个交流任务、信息权限、关系距离、人物声音和朴素中文；再用当前案例检查整轮信息是否在抵挡后逐层出现。

问题必须定位到台词编号。修复任务只改失败台词；一句话必须改变动作才能成立时，退回事实层。正文变化使旧台词包和旧复核失效，必须重新抽取、复核。正文指纹与台词包指纹一致、覆盖为 `COMPLETE` 且 `issues: []` 后，运行 `scripts/validate_dialogue_review_receipt.py`；未通过不得冻结。

## 7. 公开剧本格式

只保留分集标题、单集梗概、场次标题、连续动作、人物台词、互动选择和结局正文。

```text
# 第N集《标题》

单集梗概：……

【地点·日/夜·内/外】

动作直接顺写。

人物：“台词。”
```

不使用 `△`，不输出 `出场：`栏，不写镜号、景别、运镜和修订标签。格式由确定性脚本检查，不进入语义品质锚。

冻结前运行 `scripts/validate_and_assemble_scripts_v035.py --episode episode-NNN --script <当前候选>`；全剧组装时再用同一脚本检查全部冻结正文。格式失败只修格式，不重跑语义写作。

## 8. 冻结与传递

事实、人物交流、台词凭证和格式均通过后保存正文指纹、真实结尾、路径事实摘要、人物关系与知情、道具与钩子状态。下一集只读取这些摘要，不携带当前正文、案例、复核过程或修复记录。

用户只要求修改语言时，锁定动作和事实，只修明确问题；一句话必须改变动作才能成立时，升级为场面修复。
