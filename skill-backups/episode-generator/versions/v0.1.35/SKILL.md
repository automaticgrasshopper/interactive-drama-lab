# 分集规划师

规范版本：`v0.1.35`。新建项目缓存版本：`episode-cache-v0.1.35`。

## 核心原则

- 一个流程节点就是一集；选择结果、反馈、汇合和结局也是独立分集。
- 情绪脊决定拐点和开扇位置，人物的可执行行动决定选项内容；两者必须同时成立。
- “包子原则”约束每集梗概：普通事件是外皮，项目独有规则或题材反差是馅，结尾继续沿这份馅升级。
- 每一阶段只读取白名单输入，输出封存后再进入下一阶段。
- 用户确认的拓扑是写作锚。未重新解冻前，逐集写作、润色和验收都不得改变节点、边、选项、汇合或结局条件。

## 权威顺序与引用边界

发生冲突时依次服从：

1. 用户明确要求与冻结上游事实。
2. 已确认的拓扑锚。
3. 当前阶段最小输入包。
4. `reference-manifest.json` 为当前阶段列出的参考文件。
5. 通用写作习惯。

只有 `reference-manifest.json` 当前版本列出的文件有效。目录中未被清单调用的旧 reference 视为历史材料，禁止通过搜索结果自然混入当前阶段。

同一任务的对话历史可能仍在模型上下文中，但历史内容不自动成为制作输入。当前阶段只能引用最小输入包；历史说法与冻结包冲突时，以冻结包为准，并把冲突作为失效事件处理。

## 输入要求

必须完整读取：

- `游戏企划`
- `角色描述`
- `场景描述`
- `道具描述`

缺少哪一项，只追问哪一项。用户明确给出的主线、关系、世界规则、关键事件、节点建议、结局数量和结局方向优先。

## 固定公开输出

拓扑阶段只公开：

1. `episode-synopsis.md`：分集编号、标题、梗概。
2. `episode-flowchart.svg`：真实分集、选项、跳转、汇合与结局。

用户确认拓扑后才继续生成：

3. `episode-script.md`：全部冻结分集剧本。

上游整理、情绪脊、候选淘汰、因果图、单集写作包、事实摘要、问题单和指纹均为制作缓存。用户明确要求调试时，只展示结构化结论，不展示逐字内部思维。

## 阶段一：冻结上游

1. 读取全部原始输入，并按 `references/upstream-input-translation.md` 整理。
2. 冻结正式人物、关系、目标、世界规则、资产名称、节点建议、必保事件与结局要求。
3. 生成 `upstream-reference.md` 和内容指纹。后续规划不再反复携带原始全文。
4. 若冲突会改变核心目标、关系、规则、节点总量或结局，停止并提出最小追问。

阶段一验收：字段齐全、正式名称一致、无主线级冲突、来源可追溯。失败不得进入规划。

## 阶段二：情绪脊、因果链与拓扑

完整读取 `references/planning-and-topology-v032.md`，只使用 `upstream-reference.md`：

1. 写私有起承转合情绪脊，登记幻想、风险、现实落点、控制权变化和下一催化。
2. 对开场钩子、首次释放、中段反噬和高潮解法各生成三个实质不同方案，强制淘汰第一直觉；只保存采用结论进入下一步。
3. 把每个情绪拐点落实为人物行动、阻力、结果和下一催化，形成因果链。
4. 扫描命令、请求、隐瞒、交易、救援、牺牲和不可逆行动；只有“至少两个合理行动”与“情绪方向真实分歧”同时成立才开扇。
5. 按真实变化拆分分集。每个选项先进入独立结果集；汇合必须保留未解决差异。
6. 对每个节点执行包子四检：具体事件、题材反差物、题材内升级、下一催化或结局余波。
7. 运行拓扑验收，通过后由同一冻结拓扑生成梗概与流程图。

用户确认后，在 `manifest.md` 保存：拓扑版本、节点与边指纹、确认状态和确认时间。任何拓扑修改都必须显式解冻，并使全部受影响分集失效；不得在写作阶段静默漂移。

## 阶段三：逐集生产

完整读取 `references/episode-production-v035.md`。严格按观看路径一次处理一集：

1. 生成当前集最小写作包，同时记录当前关系、唯一主场型和台词主导／动作主导；剧情事实、入口和出口只由这张卡负责。
2. 不加载真人案例，一次完成整场铺实：把触发、感知、反应、行动、阻力、调整或核验、可见结果、人物余波和下一行动写成连续现场。
3. 先做事实复核，只查来源、权限、事件、动作、结果和出口；通过后锁定事实层。
4. 再做人物交流复核：完整读取 `chinese-dialogue-craft.md`，并在同一轮按主场型最多加载一张案例卡；抽取全部真实台词，逐句检查话茬、名词来源、信息权限、关系距离、人物声音和朴素中文，再检查整轮信息递进。
5. 台词抽取与复核必须保存当前正文和台词包指纹、台词总数、`COMPLETE`及`issues: []`；正文变化使旧凭证失效。格式检查独立执行，动作直接顺写，不使用 `△`，不输出 `出场：`栏。
6. 事实、人物交流、凭证和格式均通过后冻结正文、事实摘要和观众摘要，再进入下一集。

当前集不得读取：原始上游全文、情绪数值、淘汰候选、其它路线正文、未来结局正文、已冻结前集全文。需要的前情只能来自路径事实摘要和直接前置真实结尾。

## 阶段四：全剧验收与组装

全部分集冻结后才执行：

- 拓扑与剧本跳转一致；
- 每条观看路径事实连续；
- 人物知情、关系、道具和钩子轨迹连续；
- 分支差异在汇合与结局中得到回收；
- 正式结局和失败小结局均由此前选择造成；
- 公开梗概、流程图和剧本来自同一拓扑锚与冻结正文。

终验只读取冻结拓扑、逐集事实摘要、路径轨迹和冻结正文，不读取淘汰候选、情绪数值或写作问题单。通过后组装公开文件。

## 修改与恢复

- 改上游事实：从上游冻结开始失效。
- 改节点、选择、边或结局条件：解冻拓扑，并使受影响分集及下游失效。
- 只改某集场面或台词：只解冻该集；若真实结尾变化，再失效直接后续。
- 只改语言：锁定场次、动作、事实、选择和真实结尾，只修用户指出或复核定位的表达问题；没有明确语言问题时不改。
- 已冻结且输入指纹未变化的阶段不得重做。

## 总验收标准

- 四类上游输入完整并已冻结。
- 情绪脊、因果链、拓扑依次完成，没有倒填。
- 四个关键拍位完成第一直觉淘汰。
- 每个选择同时满足有效行动与情绪分歧，不为配额增加。
- 一个节点就是一集，编号唯一，所有节点可达。
- 每个选项先进入不同结果集，汇合不清除有效差异。
- 每集通过包子四检，并写清核心变化和下一催化。
- 结局数量、方向、所得、失去和价值判断符合上游。
- 拓扑确认后具有稳定指纹，剧本没有改动拓扑。
- 每集依次完成最小写作包、场面铺实、事实复核、人物交流复核和格式检查。
- 每次模型任务只处理一集的一个问题；当前集未冻结，不得领取下一集任务。
- 人话规则与当前唯一场型案例只在人物交流复核同一轮加载，不进入写作、事实复核、状态摘要或后续集上下文。
- 人物交流复核覆盖全部真实台词；正文指纹、台词包指纹、台词总数、`COMPLETE`或问题记录任一缺失时不得冻结。
- 多人交流场默认台词主导；动作明显多于台词时，检查是否用动作代替了人物判断、关系攻防和决定，不为比例填充空台词。
- 剧本动作直接顺写，不含 `△` 和 `出场：`栏；格式规则不进入项目品质锚。
- 最终公开文件来自同一份确认拓扑和冻结正文。

## 触发测试 Prompt

- `Use $episode-generator：读取这份游戏企划和资产，先完成上游冻结、情绪脊和一集一节点拓扑，公开梗概与流程图后等待确认。`
- `Use $episode-generator：按已确认拓扑从第1集开始，逐集执行最小写作包、整场铺实、事实复核、人物交流复核和冻结。`
- `Use $episode-generator：检查汇合后是否丢失前面选择造成的信任、资源或知情差异。`

## 不应触发的反例 Prompt

- `把一句话脑洞写成游戏企划。` 应使用大纲生成师。
- `把企划拆成角色、场景和道具描述。` 应使用资产设计师。
- `把第3集拆成镜头并生成图像提示词。` 应使用分镜相关 Skill。
