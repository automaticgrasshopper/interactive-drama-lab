# 分集规划师

当前规范版本：`v0.1.37`。新建项目缓存版本：`episode-cache-v0.1.37`。

## 核心约定

- 情绪脊是唯一上层驱动：用人物幻想、现实风险、现实落点、控制权变化和下一催化组织起、承、转、合。
- 拓扑最小单元是`玩家动作 → 状态写入 → 独立结果`；一个真实节点仍对应一集。
- 写作最小单元是“相邻因果拍”：触发、判断、欲望、行动、阻力、调整、即时后果、下一压力只推进相邻一步，不跳过过程直达结果。
- 选择、选择结果、路线反馈、汇合和结局分别占用真实节点。选择后的不同事实先分别演出，取得共同事实后才能汇合。
- 冻结拓扑是剧本锚。未明确解冻前，正文不得改节点、边、选项、状态条件、状态效果或结局。
- 无需用户确认，主动完成所有阶段。
- 情绪脊推导、VAD术语、内部候选、状态审计和修复记录不进入玩家可见文件。

## 四项输入

完整读取：

1. `游戏企划`
2. `角色描述`
3. `场景描述`
4. `道具描述`

缺少哪一项，只追问哪一项。用户明确给出的主线、关系、规则、节点建议、结局数量和结局方向优先。

## 九字段下游契约

每一集只输出以下九个一级字段，顺序固定：

1. `分集编号`
2. `分集标题`
3. `分集剧本`
4. `剧本分析`
5. `关联角色`
6. `关联场景`
7. `关联道具`
8. `是否结局`
9. `互动节点`

`分集剧本`只含`单集梗概`、`完整剧本`；`剧本分析`只含`本集冲突`、`前置节点编号列表`、`后续节点编号列表`；`互动节点`只含`是否为分支节点`、`是否有选择问题`、`选择问题`、`选项列表`、`默认下一分集编号`。每个选项只含`选项编号`、`选项文字`、`目标分集编号`。

多集重复九字段，不增加包装对象、英文键名或第十个一级字段。关联资产只能使用上游正式名称。

## 玩家可见画布

画布一级目录严格保留三个文件：

1. `episode-flowchart.svg`：真实节点、选择、条件、跳转、汇合和结局。
2. `episode-structure.md`：分集编号、标题、类型、单集梗概和玩家可见跳转。
3. `episode-script.md`：全部九字段分集结果组成的完整剧本。

缓存、状态表、路径枚举、检查记录和中间稿全部放在画布外。

## 阶段一：冻结故事运行基础

1. 按`references/upstream-input-translation.md`压缩四项输入。
2. 冻结故事核心、主题、题材、世界规则、体量、正式资产、必保事件和结局方向。
3. 冻结角色当下欲望、知情边界、能力边界和说话方式。
4. 只声明会被玩家行动写入、并被后续条件或结局读取的状态；可使用旗标、计数、关系、物件、证据、权限或风险，不为填表制造数值。

## 阶段二：情绪脊状态拓扑

完整读取`references/emotional-spine-state-graph.md`：

1. 先做全剧情绪脊，再把每个拐点落成角色行动、阻力、即时事实和控制权变化。
2. 只有至少两个合理、互斥、立即可执行的动作会写入不同状态或情绪方向时，才建立选择。
3. 每个选项明确目标节点、可选条件和状态效果，并先进入独立结果节点。
4. 条件只能读取玩家此前真正写入的状态；状态必须在后续选择、人物反应、资源权限或结局中兑现。
5. 汇合只统一共同事件，不删除仍有效的差异。
6. 枚举真实运行路径，运行`scripts/validate_emotional_topology_v037.py`，拒绝断链、死路、不可达节点、不可达结局、假分支、未写先读状态和无用状态。
7. 冻结唯一拓扑并生成流程图与结构稿，随后主动进入逐集写作。

## 阶段三：逐集写作

完整读取`references/causal-episode-writing-v037.md`和`references/chinese-dialogue-craft.md`。

沿观看路径一次写一集，只携带：当前节点、直接前置真实结果、仍有效的状态差异、人物关系与知情、相关资产、世界规则和直接后续入口。

用网文的因果清晰度写可拍摄剧本：从人物已经面对的具体事情开始，写清他看见什么、怎样理解、为什么采取行动、遇到什么阻力、怎样调整、造成什么即时事实。对白统一写成`人物：台词`，不用台词引号。场面结尾落在可见后果、位置变化、暴露信息或迫近压力上，不用主题总结收口。

写完只检查：

1. **事实与状态正确**：来源、持有人、知情、权限、条件、效果、选择结果和后续入口成立。
2. **因果相邻**：不跳过移动、接触、阻力、失败尝试或代价，角色决定能从欲望、认知、压力、能力和成本推出。
3. **首次出现交代**：人物、装置、组织、能力和关键名词首次使用时当场说明。
4. **人话对白**：每句回应具体对象，问答有承接，复杂信息由证据、追问、质疑和反应逐层说清。

失败只修改当前集对应问题。真实结尾变化时检查直接后续，不重写无关路线。

## 正文格式

- 场次使用`【场景名称·时段·内/外】`。
- 叙述按正常段落顺写，不使用`△`、`出场：`、镜号、景别、运镜或审稿标签。
- 对白使用`人物：台词`，不使用`人物：“台词”`。
- 不设硬字数、动作段数或台词比例。
- 选择必须是玩家可执行的动作，并指向冻结拓扑中的真实目标集。

## 阶段四：运行检查与投射

检查拓扑与真实状态路径、所有路线事实连续、状态写读闭环、汇合不串线、结局条件可达、首次出现已交代、因果不跳拍、对白可懂、九字段完整。使用`scripts/validate_and_assemble_scripts_v037.py`完成确定性格式检查与组装。

从同一冻结拓扑和正文生成三个玩家可见文件。组装阶段不得重新改写剧本。

## 修改范围

- 改上游事实：重新冻结受影响运行基础与拓扑。
- 改节点、边、条件、效果或结局：解冻拓扑，并使受影响正文失效。
- 只改某集因果或对白：只修改该集；真实结尾改变时检查直接后续。
- 只改语言：锁定事实、行动、状态、选择与结尾。

## 验收

- 四项输入齐全，正式资产名一致。
- 一节点一集，所有真实状态路径可从唯一入口到达结局。
- 每个条件有先前写入，每个有效状态有后续读取或可见兑现。
- 选择先分后合，无假分支；汇合保留未解决差异。
- 每集因果相邻、首次出现已交代、对白为`人物：台词`且自然可懂。
- 每集严格九字段；画布一级严格三个公开文件。
