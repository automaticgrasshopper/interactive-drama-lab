# 上游输入转译规范

用于四项正式输入通过完整性门禁之后、建立情绪脊与拓扑之前。目标不是扩写大纲，而是把可能冗长、重复或逻辑不通的原始资料整理成唯一生产参考。`input.md` 始终原样保存；先运行`python3 {skill-root}/scripts/prepare_upstream_packet.py {cache-root}`机械生成白名单阅读包，当前主 Agent只读取`upstream-packet.md`完成语义转译。转译完成后，阶段一及后续生产不得重新读取原始 `input.md` 补充故事。

## 一、读取白名单

完整读取`游戏企划`，包括以下原字段：

1. 游戏标题
2. 一句话概述
3. 游戏核心目标
4. 游戏关键词
5. 时代与地点
6. 玩家身份与视角
7. 剧情整体描述
8. 游戏核心冲突
9. 游戏世界观
10. 游戏基调与情绪
11. 游戏主题
12. 游戏体量
13. 推荐结局数
14. 结构信息：游戏结构类型、剧情节点总数建议、结局构成、主线情绪变化、给分集的重点提醒
15. 待确认问题，仅在原输入确有该项时读取

游戏企划含资产设计材料时，完整读取`核心人物与关系方向`、`关键场景方向`、`关键道具与视觉符号`、`影响资产的剧情节点与状态变化`、`资产一致性要求`、`安全与生成限制`和`参考材料边界`。

`prepare_upstream_packet.py`从角色、场景、道具只抽取以下原字段，当前主 Agent禁止直接打开原始资产段落或把其它字段带入转译上下文：

- 角色：`角色名称`、`身份定位`、`人物驱动力`、`人物弧光`、`外貌特征`、`人物关系`。
- 场景：`场景名称`、`场景描述`。
- 道具：`道具名称`、`道具形象描述`、`道具意义`。

原始资料中的角色类型、标签、特征、年龄、性别、气质、性格、情感依托、标志性动作、声音气质、叙事功能、固定特征、允许变化、必须保持一致、相关资产、视觉风格、空间布局、识别元素和固定空间关系均不进入生产参考。它们仍保留在`input.md`，但不得在阶段一以后重新读取以影响结构、场面或对白。

## 二、固定事实与可转译范围

以下内容只允许压缩、去重和换序，不得改变：

- 用户明确指定的题材、玩家身份、核心目标、体量、结局数量和结局方向；
- 正式角色、场景、道具名称；
- 角色身份定位、人物驱动力、人物弧光、外貌特征和人物关系；
- 场景本身是什么地方；
- 道具长什么样和原本具有什么意义。

以下内容允许为建立可生产逻辑而重新整理：

- 重复或同义的概念、规则与人物功能；
- 信息顺序、主次关系、支线数量和结构复杂度；
- 抽象作者解释与观众实际需要理解的规则之间的表达；
- 不成立、缺环或互相矛盾的中间因果；
- 原大纲中尚未执行到场面颗粒的事件连接方式。

转译不得新增人物、地点、道具、世界规则、关键权限、前史秘密或结局。若修复主线必须改变固定事实或新增上述内容，把冲突写入`待确认问题`并停止；不得开始情绪脊或拓扑。

## 三、转译顺序

### 1. 简化结构

先用三至五句话复述故事。复述不成立时，依次处理：

1. 只保留一个主角当前主线目标和一个不行动后果；
2. 合并不产生不同结果的重复关系线、机构、规则和装置；
3. 删除只解释主题、不改变人物下一行动、关系、信息、风险或行动权的结构层内容；
4. 把作者概念改写为人物可遭遇的事实，但不下探到场次、走位、对白或镜头；
5. 保留用户锁定的结局数量与价值差异，不先建立分集节点。

简化不是另写一个故事。原大纲的核心承诺、人物目标和结局方向必须仍可逐项对应。

### 2. 确立主干情绪脊

只到起、承、转、合的粗颗粒：

- 起：主角缺什么、受什么压制、当前想完成什么；
- 承：采取什么方向的行动，获得什么可见成果或关系靠近；
- 转：前述成果携带的风险如何反噬，使判断、关系或行动权发生反号；
- 合：玩家通过什么最终价值选择夺回、交出或重新定义行动权，各结局落在哪里。

每次情绪变化必须对应获得、失去、关系、信息、风险或行动权的真实变化。PAD/VAD、概率和力度只用于这一阶段内部校准；`upstream-reference.md`只保存可读的阶段事实与变化原因，不向生产卡和正文传递数值。

### 3. 建立核心因果链

把主线写成连续链：

`前置事实 → 人物行动 → 直接状态变化 → 下一事件为何发生 → 最终结果`。

逐箭头检查：

- 行动者是否已在场并拥有所需信息、权限、资源与动机；
- 结果是否由行动造成，而非主题、称谓、关系好坏或系统自动判定；
- 后续人物如何知道该结果，物件或信息如何移动；
- 世界危机、关系变化和结局是否共用同一条已建立的因果，而非高潮另开规则；
- 去掉任一箭头后是否会出现“刚好、突然、原来还有一个规则”。

能用更少概念建立同一核心逻辑时，使用更少概念。核心因果未闭合时不得用拓扑补洞。

### 4. 按原字段名转译企划

整理后的游戏企划继续使用原来的十五项字段名；`结构信息`继续使用五个原子字段名。资产设计材料存在时继续使用七个原字段名，但压缩到只表达方向、一致性和边界，不把完整资产字段复制回来。

不得在转译阶段生成分集编号、场次、对白、逐动作施工图、具体镜头、生产卡或拓扑边。`剧情节点总数建议`只保留上游已经指定的数量，或在上游明确授权建议时给粗颗粒总量；不得先拆节点再反写大纲。

## 五、冻结与读取纪律

1. 运行白名单抽取脚本并只读取`upstream-packet.md`；计算原样`input.md`去除首尾空白后的 SHA-256，写入来源指纹。
2. 当前主 Agent逐项完成四项语义校验，依据必须指向整理后的具体内容；确定性脚本只能验证格式、白名单、指纹和状态，不能生成语义 PASS。
3. `待确认问题`存在会改变玩家身份、核心目标、固定人物关系、世界规则、关键道具来源、分支或结局的未决项时，`未解决问题`不得写`无`，并停止生产。
4. 四项均 PASS、未解决问题为`无`且来源指纹一致后冻结`upstream-reference.md`。
5. 阶段一只读取冻结的`upstream-reference.md`。建立`global.md`、候选互动、情绪脊和拓扑时不得再读取`input.md`或资产非白名单字段。
6. 转译参考修改会使全局事实、情绪脊、候选互动、拓扑、生产卡及全部正文失效；返回本阶段重新冻结，不做局部补丁。
