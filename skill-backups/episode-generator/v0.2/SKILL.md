# 分集规划师

## 目标

把已确认的游戏企划和角色、场景、道具描述，分两轮生成互动分集剧本：

1. 第一轮完成字段筛选、事实与规则检查、情绪脊、分集拓扑和全部单集生产卡。
2. 第二轮不重新推导结构、情绪脊、人物弧光或结局，只按冻结的单集生产卡把剧情写成动作和中文台词。

上游原始资料全量保留为事实源，但不在每一阶段全量载入。内部规划、阶段交接和最终下游传参均使用固定标题的自然中文，不以 JSON 作为默认工作或交付格式。

## 上游输入

必须收到四个一级字段：

- `游戏企划`
- `角色描述`
- `场景描述`
- `道具描述`

上游可以传入全部子字段。本 Skill 使用字段路由而不是要求上游删减字段。

### 第一轮读取的字段

`游戏企划`：

- 游戏标题
- 一句话概述
- 游戏核心目标
- 时代与地点
- 玩家身份与视角
- 剧情整体描述
- 游戏核心冲突
- 游戏世界观中实际限制行动的规则和代价
- 游戏基调与情绪
- 游戏体量
- 推荐结局数
- 结构信息的全部内容
- 会改变身份、目标、关系、规则、分支或结局的待确认问题

`游戏关键词`和`游戏主题`不参与节点推导，只在结构完成后用于检查是否偏题。

`角色描述`：

- 角色名称
- 角色特征
- 身份定位
- 性格中会影响选择的部分
- 情感依托
- 人物驱动力
- 人物弧光
- 人物关系
- 叙事功能

`场景描述`：

- 场景名称
- 场景描述
- 空间布局中影响人物行动的部分
- 叙事功能
- 固定空间关系
- 必须保持一致

`道具描述`：

- 道具名称
- 道具意义中的剧情功能
- 允许变化的状态
- 必须保持一致
- 相关资产，仅用于定位可能的场景和持有者

道具描述若无法确定首次出现位置、当时持有者或取得方式，不得自行把道具放入剧情。该信息若影响主线，列为待确认问题；若可由已确认的场景关系唯一推导，将推导结果写入生产卡。

### 第二轮按需追加的字段

只对当前集实际出现的资产追加读取：

- 角色：年龄、性别、气质、外貌特征、标志性动作、声音气质、固定特征、允许变化的状态、必须保持一致。
- 场景：场景识别元素、允许变化的状态、相关资产。
- 道具：道具形象描述、固定外观。

`如何符合所选视觉风格`不进入分集剧本上下文；由下游分镜或视觉技能使用。

## 输入门禁

- 四个一级字段缺少任意一个时，不开始分集规划。
- 只有名称或标识、没有实际描述时，视为缺失。
- 会改变玩家身份、核心目标、人物关系、世界规则、分支或结局的冲突，必须先解决。
- 不影响上述结构的次要缺口不阻塞规划，但不得用新设定填补。

## 第一轮：结构确认

### 读取资料

必须读取：

- `references/production-protocol.md`
- `references/emotional-spine-and-branching.md`

只在悬疑、惊悚、犯罪、反转、秘密、证据或信息延后揭露题材中追加读取：

- `references/causal-clarity-and-suspense.md`

第一轮不读取台词、金样例或制片格式资料。

### 内部工作

1. 把第一轮必需字段压缩为事实基线，原始资料仍保留为可回查来源。
2. 确定节点数、结局、选择和汇合。
3. 按情绪脊说明书完成整体起承转合，并在每集内部标注情绪起点、变化原因和情绪落点。
4. 建立唯一的分集拓扑，每个节点只保存真实入边、出边和选项。
5. 为每集建立一张自然中文`单集生产卡`。
6. 对关键节点执行题材透镜检查：反差物是否具有题材辨识度、结果是否在已建立规则内升级、结尾是否逼出下一行动或悬念。
7. 按生产协议逐项自检；任何一项失败都返回情绪脊、拓扑或生产卡重做。
8. 只有全部检查通过，才从拓扑和生产卡投射用户可见的流程图和单集梗概。

### 单集生产卡

每张卡使用简短自然中文记录：

- 本集编号、标题和单集梗概
- 本集冲突与前后承接
- 前置节点编号列表
- 后续节点编号列表
- 本集在整体结构中的作用
- 情绪起点、变化原因和落点
- 每条直接前置集写了什么、以什么场景和状态结束
- 上一选择或结尾事件在本集必须先演的行为、反应和即时结果
- 本集的具体起因、行动、阻力、结果和钩子
- 开场与结尾的时间、地点、在场人物和人物位置
- 人物关系、已知信息和风险在本集前后的变化
- 本集实际使用的角色、场景和道具
- 关键物件的来源、持有者、位置、使用方式、代价和结尾状态
- 每个直接后续集已经确定写什么、它的进入条件，以及本集必须造成的结尾

`本集冲突与前后承接`在第一轮直接生成，用一段精简自然中文说明本集如何承接上集、谁要做什么、受到什么阻力、关系或信息如何变化，以及结尾如何进入下集。前置和后续节点编号列表直接从拓扑入边和出边生成。

生产卡是第一轮的完整交接材料。用户确认结构后，`单集梗概`、`本集冲突与前后承接`、`前置节点编号列表`和`后续节点编号列表`与其它生产卡内容一同冻结。第二轮不再重新推导或概括它们，只读取并执行。

### 单集梗概规则

- 原则上使用一句冷静、客观、凝练的自然中文。
- 让读者能看懂谁因为什么，在哪里做了什么，受到什么阻力，最终产生什么结果和下一问题。
- 使用普通中文的主谓宾和因果连接，不使用路线说明、作者判断、程序术语或未经建置的专有名词。
- 人物姓名首次出现时，自然交代身份或与已知人物的关系。
- 场景首次出现时，说明它是什么、从哪里进入以及为什么能进入。不使用尚未建立的简称。
- 关键物件首次出现时，交代来源、当前持有人或取得方式；能力或规则首次使用时，最多用一句短句交代触发方式、可见作用和代价。完成建置后才可直接使用名称。
- 超自然能力、道具规则、证据效果和使用代价必须写成可见的动作与明确因果，不只写“验真”“烧掉记忆”“证明有关”等抽象结论。
- 作者判断必须改写为观众能看到的证据、动作、对话或结果。
- 若时间、地点和人物未变，使用“接上集”或“片刻后”，不使用无剧情价值的精确时刻。
- 指向同一后续集的所有前置集，结尾必须落到能被该后续开场直接接住的时间、地点、人物位置和物件状态；不能统一时，在后续生产卡中分别记录每条来路的开场承接。
- 关键节点必须出现题材独有的反差物，结果必须在已建立规则内升级，并产生下一行动或悬念；任一项缺失，退回重写该集梗概。
- 不拆成时间、地点、人物、起因、经过、结果六个标签。

### 选择与承接

- 每个选项使用“动词＋明确对象”，只写玩家此刻要做的动作，不写态度、抽象结果、代价说明或多步行为。
- 特殊行动第一次成为选项前，最多用一句短句说明如何做、会发生什么和要付什么代价。
- 调剂选择改变即时反馈或局部状态，经过不同结果节点后可以较快汇合。
- 重大选择必须进入结局，或展开至少三个连续节点的不同剧情线；是否最终汇合或形成小结局，由该路线的情绪落点和行动权变化决定。
- 结构确认稿中的选项后写明`→ 进入第 N 集《标题》`。
- 选项只是玩家指令，不代表行为已经发生。
- 目标集默认从选择当下的同一时间、地点、在场人物和人物位置开场，先演出选择行为、对方反应和即时结果，再由该结果触发转场。
- 只有选项本身就是离开、前往或立即切断当前场景的行动时，目标集才可以直接转场。

### 第一轮用户可见输出

第一轮输出必须已经通过内部自检；不展示未通过的草稿和重跑过程。

只展示：

1. 基于冻结拓扑的 Mermaid `flowchart`。
2. 每集的编号、标题和`单集梗概`。
3. 分支节点的精简选择及目标分集。

不展示情绪脊、生产卡、内部状态、路径统计和规则推导。

结尾询问：

`分集流程和单集梗概如上。需要调整，还是按这个结构继续写完整剧本？`

用户修改任一节点时，同步重算受影响的情绪段、拓扑边、生产卡和直接相邻节点，再重新提交结构确认稿。

## 第二轮：完整剧本

### 读取资料

结构确认后，冻结拓扑和全部生产卡，包括每集的`单集梗概`、`本集冲突与前后承接`、`前置节点编号列表`和`后续节点编号列表`。第二轮只额外读取一次：

- `references/chinese-dialogue-craft.md`
- `references/gold-sample-episode.md`

输出格式直接使用本 SKILL 后文，不再读取其它结构、情绪、场景展开或制片格式说明书。

### 逐集写作

按拓扑顺序一集一集执行。写当前集时只载入：

- 当前集生产卡
- 已冻结的单集梗概
- 已冻结的本集冲突与前后承接
- 已冻结的前置节点编号列表和后续节点编号列表
- 每条直接前置集已验收的真实结尾
- 每个直接后续集的生产卡中与进入条件有关的部分
- 当前集实际使用的角色、场景和道具补充字段

不再载入全局情绪脊、分支理论、全部人物资料、全部场景道具或已完成的全部剧本。

每集写完后内部暂停并检查：

1. 开场是否实际演出前置选择或结尾事件。
2. 人物、场景、物件和已知信息是否与前置真实结尾一致。
3. 生产卡的事件、关系变化和可见证据是否在正文中发生。
4. 正文是否完整执行已冻结的`本集冲突与前后承接`。
5. 结尾是否真实产生后续集需要的进入条件。
6. 台词是否使用普通、可理解的中文，并与金样例的信息推进方式一致。

通过后冻结本集，把真实结尾回写到直接后续集的前置记录，然后自动继续。若正文与已冻结的单集梗概或本集冲突与前后承接不一致，优先返工正文，不根据写偏的剧本反向重写第一轮参数。

用户只收到一次完整交付，不看到内部分批、暂停和校验。

## 完整剧本格式

每集用普通 Markdown 逐行书写：

```text
# 第N集《标题》

单集梗概：……

【场一 · 地点 · 日/夜 · 内/外】
出场：人物

△ 可拍摄的动作或环境变化。

人物：台词

选择：
- 一个明确行动 → 进入第N集《标题》
```

不得把完整剧本放入代码块、表格、引用块或卡片。上述代码块只用于说明格式，正式交付使用普通正文。

选项后的剧情在目标集中发生。目标集开场先演出选择行为、对方反应和即时结果，不把选项文字当成已经演完的剧情。

## 自然参数交给下游

最终不生成 JSON。对每一集使用以下自然中文参数：

- 分集编号
- 分集标题
- 单集梗概
- 完整剧本
- 本集冲突与前后承接
- 前置节点编号列表
- 后续节点编号列表
- 本集使用的角色
- 本集使用的场景
- 本集使用的道具
- 是否结局
- 选择问题、选项文字和对应目标分集，或默认进入的下一集

`本集冲突与前后承接`直接使用第一轮生成并冻结的原文，不在第二轮根据完整剧本重新概括。它用一段自然中文说明本集如何承接上集、谁做什么、受到什么阻力、关系或信息如何变化，以及结尾如何进入下集。

用户默认只看分集编号、标题、单集梗概、完整剧本、玩家可见选择和结局正文。其余自然参数直接传给下游，不必向用户展示。

## 验收

### 第一轮

- 四个一级输入齐全，字段筛选正确。
- 情绪脊已完成并投射到每集生产卡。
- 每集的单集梗概、本集冲突与前后承接、前置节点编号列表和后续节点编号列表已生成并冻结。
- 节点全部可达，无循环、孤立、断头和无出边的非结局节点。
- 流程图、选项目标、单集梗概和生产卡来自同一拓扑。
- 每集生产卡已保存直接上下集、承接状态、人物关系、信息、场景和道具状态。
- 梳概中没有未建立场景、无来源物件、抽象能力或无法拍摄的作者结论。
- 选项采用“动词＋明确对象”，首次出现的特殊行动已用一句短句建置，目标集的生产卡先演选择再转场。
- 调剂选择与重大选择已经分级；重大选择直达结局或拥有至少三个连续差异节点，调剂选择拥有不同即时结果。
- 关键节点均通过题材透镜检查，题材反差物、规则内升级和下一行动或悬念三项齐全。
- 已逐边完成相邻集承接检查；所有合流前置集的结尾都能被后续开场接住，不能统一的来路已分别记录，所有条件边均为真实可走边。
- 首次出现的人物、场景、道具和规则已经建置，不存在未经解释的术语或不自然的中文表达。
- 已完成第一轮自检；任一项失败时已经返回对应步骤重做，没有带错输出。

### 第二轮

- 每集只执行冻结生产卡，没有重新设计情绪脊、人物弧光、分支或结局。
- 完整剧本依据第一轮冻结的单集梗概和本集冲突与前后承接生成；不在第二轮重写这两项。
- 每个非首集开场都与直接前置集的真实结尾连续。
- 选择行为、人物反应和即时结果已在目标集中实际演出。
- 规则、证据、物件来源、持有变化和使用代价通过动作或台词让观众看懂。
- 单集梗概与完整剧本覆盖同一段剧情。
- 当前集结尾真实产生直接后续集需要的进入条件。
- 中文台词清楚、自然，不以谜语、抽象结论或设定说明替代人物行动。
- 最终使用自然中文参数交给下游，不生成 JSON。

## 失败处理

- 结构不清或无法说明因果：返回第一轮修改情绪脊、拓扑或生产卡。
- 场景、物件或规则突然出现：先查上游原始资料；无法唯一推导时不继续编造。
- 下一集跳过选择或直接换场：返工目标集开场，先演选择行为和反应。
- 剧本与冻结生产卡冲突：优先返工当前集；只有规划本身不成立时才回到第一轮。
- 长剧本后段缩水：继续内部逐集生成和校验，不改为一次性长写。

## 边界

- 不创作新游戏企划、新角色资产、新场景资产或新道具资产。
- 不生成分镜、镜头、图像提示词或视频提示词。
- 不复制金样例的人物、题材、台词或情节，只学习信息推进、人物交锋和格式。
