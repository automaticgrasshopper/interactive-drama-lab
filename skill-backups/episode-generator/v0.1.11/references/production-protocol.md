# 分集画布生产协议

规定从上游输入到最终完整剧本的唯一执行顺序。流程在一次任务中自动连续执行；流程图、内部批次、逐集校验和修复均不产生阶段性消息。

## 一、读取阶段资料

### 全局规划阶段

读取：

- `emotional-spine-and-branching.md`
- 悬疑、惊悚、犯罪、反转、秘密或证据延后揭露题材再读 `causal-clarity-and-suspense.md`
- `canvas-cache-protocol.md`

### 剧本执行阶段

读取：

- `script-execution-and-validation.md`
- `chinese-dialogue-craft.md`

当前执行组包含谈判、审讯、威胁、举证或由具体条件长出的互动时，再读取 `gold-sample-episode.md`。发现、日常交流、独处反应和事件驱动场景不得套用其对抗结构。

不把所有资料同时加载到单场对白上下文。

## 二、输入与事实门禁

确认`游戏企划`、`角色描述`、`场景描述`和`道具描述`完整。

建立事实基线：

- 主角身份、处境、目标和不行动的后果；
- 主要人物欲望、关系、知情范围和隐瞒；
- 已发生的前史因果；
- 世界规则的可见效果、限制与代价；
- 场景入口、出口和固定连接；
- 关键物件初始来源、持有者和状态；
- 各结局结果、所得和代价。

输入冲突按明确指令优先、正式字段优先、具体描述优先于概括描述的顺序统一。仍有多种会改变玩家身份、核心目标、人物关系、世界规则、关键道具来源、分支或结局的有效解释时，使用 `ask_user` 请求最小必要澄清；次要歧义采用对核心目标、人物关系和既有资产改动最小的解释并写入隐藏缓存。不得询问 Canvas 路径、阶段确认或是否继续。

## 三、全局情绪与拓扑

1. 根据游戏体量和结构信息确定节点数、正式结局和互动预算。
2. 从上游内容提取关系目标、核心任务目标和当前情绪；上游未提供结构化分支时不得跳过。
3. 登记幻想、实现概率、反讽风险、负面剥离点和正面认领点，建立保留关键决定为未决状态的主干情绪脊。
4. 对命令、请求、交易、威胁、隐瞒、救援、牺牲、有限资源和不可逆操作执行行动岔口扫描，建立候选互动表。
5. 用可执行性、互斥性、即时状态差、代价、VAD 方向差和互动预算筛选候选；不得因为默认主干偏好其中一个动作而删除另一动作。
6. 对上游起承转合执行商业力度验收：起有压制和目标，承有行动成果，转让成果携带的风险反噬，合回收前置选择并完成控制权变化。
7. 每集记录情绪起点、变化原因和落点；主要拍位同时记录玩家期待、实现程度、反讽风险和控制权变化。
8. 每个选择记录即时行为、戏剧功能、情绪/关系/风险差异和后续状态。
9. 调剂选择有不同即时结果后可较快汇合；重大选择直达结局或展开至少三个连续差异节点。
10. 完成分支遗漏审计和前五分钟交互检查，再将所有节点、边和结局冻结为唯一拓扑。

情绪不能只靠氛围、台词或新线索变化；必须由获得、失去、关系、信息、风险或行动权变化造成。连续节点只增加信息，却不改变人物下一行动、关系、风险或行动权时，返回情绪脊重做。

PAD/VAD、力度阈值、实现概率、互动预算和路径统计只服务本节的节点编排与拓扑验收。拓扑冻结后，将每个节点转换为定性的体验功能、入口事实和出口条件；生成梗概、生产卡和完整剧本时不读取数值，不用数值倒推人物动作、关系变化、权力翻转、对白或互动。

## 四、建立画布缓存

按 `canvas-cache-protocol.md`：

1. 定位 Canvas。
2. 创建 `.episode-cache/`。
3. 写入 manifest、全局事实、拓扑、人物、物件和钩子缓存。
4. 为每个节点创建分集文件和生产卡。
5. 运行拓扑、情绪、因果、承接和梗概校验。

生产卡冻结入口事实、核心事件结果、路径状态和出口条件，不预写每个动作、反应和台词。核心关系或个人创伤会被触发时，另写人物当前最怕失去或最想挽回的对象、未解决心结，以及核心事件对他的意义；这组定性事实只驱动人物反应，不规定情绪数值或固定表演。内容阶段可以补足不改变核心事实的日常连接动作；若生产卡必须新增世界规则、关键证据、特殊权限或人物关系才能演通，返回第一阶段修订生产卡。

第一阶段失败时只修改缓存中的对应层，不进入完整剧本。

## 五、写入结构并继续

将冻结拓扑投射为：

- 静态 SVG 流程图及折叠的 Mermaid 可编辑源码；
- 全部分集编号、标题和单集梗概；
- 玩家可见选择和目标集。

写入 Canvas 公开层，不发送阶段性消息，立即进入完整剧本阶段。输入明确只要结构时，才以结构稿结束本次任务。

## 六、按执行组滚动生成

先按拓扑划分执行组：线性连续段同组；互动节点与全部即时结果同组；汇合节点同时载入全部来路；最终选择与全部直接结局同组。批次不按固定集数划分。

每组开始前估算上下文，为输入、正文、双校验和自动修复保留容量。超出容量时只在状态稳定边界拆分，不拆开选择与结果、铺垫与反转、汇合与来路、终局选择与结局。

按执行组处理：

1. 读取组入口、组内生产卡、组出口条件、组内实际资产状态，以及核心场面相关人物的当前情感得失、关系状态和未解决心结。
2. 按组内拓扑写连续戏。
3. 按中文对白规则调整台词。
4. 按普通 Markdown 转换为制片格式。
5. 将真实完整初稿写入各分集缓存，不得用完成状态或公开稿引用代替正文。
6. 逐集先运行篇幅与动作段机械门禁，再调用中文对白校验与因果连续性校验。
7. 组内交叉校验互动兑现、分支差异、定性体验兑现和结果力度。
8. 失败时按建议修改失败场次或受影响节点并复检。
9. 全组通过后冻结组内各集，回写真实状态，并投射公开逐集文件。
10. 自动继续下一执行组。

剧本写作不重新设计情绪脊、拓扑、人物弧光或结局。

## 七、逐集校验代理

### 中文对白代理

输入当前集定稿候选、人物关系和声音气质、当前题材最接近的素人语料。只有谈判、审讯、威胁、举证或条件升级场面才附加《刘熙的条件》的信息递进方法。只输出：

- PASS / FAIL；
- 失败场次；
- 承重句过密、设定发布会、人物趋同或不自然来回的位置；
- 具体修改方向。

### 因果与连续性代理

输入所有直接前置真实结尾、当前生产卡、当前剧本、当前结尾和直接后续进入条件。只输出：

- PASS / FAIL；
- 人物到场原因、行动权限、事件发现顺序、人物反应和下一行动之间不成立的位置；
- 核心事件中观众无法判断人物认为它意味着什么的位置；
- 核心关系或个人得失被触发，却没有改变人物说话顺序、身体反应或行动优先级的位置；
- 物件来源、位置、移动方式和可见结果不成立的位置；
- 人物、场景、物件、知情、关系、风险和定性体验不连续的位置；
- 未执行的选择后果或未形成的后续条件；
- 具体修改方向。

由主 Agent 分两轮复检：第一轮只读检查因果、权限、反应和连续性；第二轮卸载结构任务，只读检查对白话茬、关系、当下目的、人物声音和朴素中文。两轮分别记录 PASS/FAIL 与具体位置，任一轮修改正文后必须重跑两轮。状态写入 manifest，不创建子任务、子线程或线程 ID。

## 八、全剧压缩对齐

全部节点冻结后，从缓存生成：

- 由 `topology.md` 确定性生成的静态流程图；
- 人物轨迹；
- 道具与证据轨迹；
- 钩子抛出与回收轨迹；
- 各主要路径情绪轨迹；
- 下游字段覆盖表。

运行 `scripts/render_episode_flowchart.py` 生成 `episode-flowchart.svg`，再运行其它确定性脚本和独立语义校验。公开结构页优先引用 SVG，Mermaid 只作为折叠的可编辑源码；不得假设宿主平台原生支持 Mermaid。最后运行 `scripts/build_episode_index.py`，把静态流程图和冻结的逐集源文件确定性排版成阅读页；页面构建不得消耗创作推理或产生第二套剧本。发现问题时确定依赖范围，只解冻并修复受影响节点及其直接后续。修复后重跑相关逐集与全剧校验。

## 九、最终投射与交付

从已冻结分集文件直接组装：

- 由冻结拓扑生成的 `episode-flowchart.svg`；
- 每集公开的 `episodes/episode-NNN.md`；
- 由公开逐集文件拼装的 `episode-script.md`；
- 写入隐藏分集缓存的每集下游自然参数；
- 由 `episode-flowchart.svg` 与全部公开逐集文件确定性构建的 `index.html` 阅读页。

组装阶段不重新生成剧本，不改写已通过的分集。`index.html` 直接展示流程图预览和逐集全文，不得退化为 Markdown 链接目录。收到单集修改请求时，以公开逐集文件为入口；修改通过校验后再更新对应缓存、受影响后续、汇总稿和阅读页。

Canvas 完整稿必须包含全部节点和全部结局。隐藏缓存、生产卡、校验记录和下游参数不进入公开层。最终消息只报告完成状态、校验结论和 Canvas 入口；输入明确要求在对话中展开具体内容时，才按指定范围展示。
