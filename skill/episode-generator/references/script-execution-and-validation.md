# 剧本执行与逐集校验规范

根据冻结生产卡写完整剧本时读取；不参与第一轮拓扑设计。

## 一、规则优先级

发生冲突时按以下顺序处理：

```text
事实与人物认知成立
> 已建立关系与个人得失驱动反应
> 场景完整自然
> 生产卡结果与边界得到执行
> 人物对白自然且可理解
> 制片格式正确
```

低优先级不得破坏高优先级。生产卡冻结的是入口事实、核心结果、路径状态和出口，不冻结每一个动作、反应与句子。写核心场面前读取相关人物的当前情感得失、关系状态和未解决心结，让它们决定反应顺序；不从定性体验或数值倒推动作。结构、前史、权限或人物关系有问题时返回生产卡，不用台词或旁白弥补结构缺口。

正式写正文前读取 `screenplay-forging-bridge.md`，在当前生产卡内完成写作护栏和场级施工图。它只把冻结节点转成完整场面，不改变拓扑、路径状态和九字段接口。

## 二、先写连续戏

不要直接对着动作与台词模板逐行填充。根据场面本身选择事件驱动或对抗驱动的连续因果。

事件驱动场面：

```text
正常状态
→ 事件发生并被人物感知
→ 人物依据认知、关系和个人得失作出自然反应
→ 旁人按自己所知解释或处置
→ 产生现实后果
→ 人物采取下一步行动
```

对抗驱动场面只在双方目标真实相冲时使用：

```text
人物为当前目标采取行动
→ 对方基于自身目标阻挡或回应
→ 动作和台词迫使下一次反应
→ 信息、关系、权力、目标或风险发生变化
→ 本场结果推动下一场
```

一场戏只要完整演出事件、反应、结果，并改变后续行动，就完成了戏剧任务。不要求每个角色都有独立目标，不强制冲突、关系变化、权力翻转或选择。只有一个动作和一句反应且没有结果时，应与相邻内容合并或继续展开。

核心关系或个人创伤被触发时，先写人物对失去、重逢、背叛、保护或羞耻的本能行动，再让他处理任务。关系不是一句称谓或背景字段；它必须改变说话顺序、身体反应或行动优先级。普通过场和程序角色不强制扩大情感。

新人物首次出现时自然交代出场动作、身份锚和来意。场景首次使用时说明人物为何进入；道具首次出现时交代原位置、发现者或取得过程。

## 三、关键情节与题材辨识

承担互动、反转、高潮或分集落点的关键情节必须同时具备：

1. 可见、可信、可拍摄的具体事件；
2. 只在当前题材和既有规则下成立的反差物；
3. 由人物行动造成的规则内升级；
4. 能推动下一场或下一集的结果、问题或选择。

关键反转必须来自“既有铺陈触发行动，行动造成反差结果”的连续因果。不得用无关突发事故、临时新增规则或新人物替代反转。

第一集应先建立主角的正常处境和做事方式，再让异常具体发生；让观众看懂主角为何在场、为何反应和接下来准备做什么。主要关系只需在它自然参与事件时登场。

## 四、中文对白

具体对白以 `chinese-dialogue-craft.md` 为准。写作时执行：

- 普通搭话、确认、追问、拒绝、回避、复述、迟疑和反应占多数；
- 承重句只放在举证、揭露、关系变化、规则说明、条件和决定处，不超过一场台词的三分之一；
- 连续三句都在发布背景、规则、秘密或结论时，改为可见动作、普通反应或真正存在目标阻力的来回；
- 每句重要台词都回应前一个动作、台词或眼前事件，并推动当场处置或下一行动；
- 不同人物依据身份、关系、欲望和声音气质形成不同说话方式；
- 悬疑、古装、危险关系和奇幻题材不等于短句、机锋、难以理解的隐喻或口号式表达的堆叠；
- 功能信息必须一遍听懂，悬念只保留具体问题的答案。

## 五、真人样例对照

每集初稿完成后先读取：

- `chinese-dialogue-craft.md` 中与当前题材或关系最接近的素人短剧片段；

再按场面类型有条件读取：

- 只有外部问题的解决方式会反噬人物关系时，读取《权势解围与关系反噬》；
- 只有谈判、审讯、威胁、举证或条件逐级加码时，读取 `gold-sample-episode.md` 中《刘熙的条件》；
- 发现、日常连接、独处反应和纯事件驱动场面，不为贴合样例改造成对抗。

校验只使用以上语料，禁止临时生成 AI 示例句。只比较方法，不复制台词和情节。

对照素人语料检查：

- 人物是否围绕眼前具体事情说话；
- 是否存在来意、拒绝、追问、劝说、改口和反应；
- 熟人、陌生人、上下级和对手的口气是否不同；
- 是否像真实中文交流，而不是轮流吐露资料。

对照《权势解围与关系反噬》检查：

- 人物是否因现实利益接受或拒绝帮助；
- 外部冲突的解决办法是否反过来改变关系；
- 前段表达的价值观是否被后段人物行动实际检验；
- 场景结束后是否留下必须承接的关系后果。

对照《刘熙的条件》检查：

- 每个人当下目标是否明确；
- 对方抵挡后才亮出约束力更强的证据，而非一次性集中说明全部背景；
- 证据是否改变权力和行为；
- 互动是否从具体条件与代价中自然产生。

## 六、逐集校验

每集写完后先保存完整初稿，再执行入口硬状态核对、机械完整度门禁、两类既有语义校验和有限前情冷读。不得先组装玩家可见完整剧本，再用“已完成”“与公开稿一致”等占位文字补写缓存。

因果与对白两类语义校验都是当前主 Agent 在同一个任务中的顺序复检轮，不是两个 Agent；规划、写作、修复与文件更新均不得委派。两轮通过后，可按 `per-episode-memory-and-cold-read.md` 调用只判不改的逐集隔离冷读者。每轮及独立冷读都要重新读取各自最小资料，并把当前正文 SHA-256、各检查项的具体依据和未解决问题写入缓存。

### 入口硬状态与有限前情冷读

读取 `per-episode-memory-and-cold-read.md`。先从直接前置真实结尾和当前路径缓存生成入口硬状态，核对正文使用的人物、知情、证据、道具和权限都有来源；失败时直接返回生产卡，不用对白补来源。

既有因果与对白复核通过后，再只读取观众摘要、入口硬状态和当前正文，先执行动作可拍门与对白可说门，再执行冷读六问。无法获得独立上下文时明确记录`隔离方式：最小上下文复检`，不得冒充独立裁判。

冷读失败只修定位场次。返修改过任何对白时，旧对白复核立即失效，必须重新执行 `chinese-dialogue-craft.md` 的最小上下文人话复检；改过任何动作时，旧因果复核立即失效，必须重新执行因果连续性与动作可拍门。修订正文的全部复核记录必须指向同一新 SHA-256。一次修复仍失败时返回生产卡；PASS 后生成本集六十至一百字观众摘要。

### 机械完整度门禁

默认中篇互动影视剧本的每个节点必须达到：

- 私有缓存中当前集定稿去除空白后的可见字符数为 850—1300；
- 以独立 `△` 行计数的动作段为 16—24 段；
- 私有缓存同时保存真实初稿、真实定稿和本次度量记录。

这组范围用于阻止梗概式压缩，不要求仅为达到字数增加内容。若上游明确指定单集时长或体量，先按指定体量换算并在 manifest 记录本项目门槛；未明确指定时不得自行降低。结局、失败小结局和纯选择节点也按默认门槛执行，除非上游明确要求短结局。

任一项不达标时，不进入语义校验、不组装公开完整剧本、不冻结本集。先判断是否安排了过多剧情任务；必要时把信息发现、人物理解、反应、调整和结果充分演出，但不得添加不改变人物认知、关系、风险或行动的填充动作。

### 中文对白校验

先检查：

- 承重句是否过量；
- 是否存在连续设定发布；
- 是否通过一问一答轮流说明资料；
- 人物语言是否趋同；
- 核心关系被触发时，语言是否体现真实关系距离、个人得失和当下冲动；
- 每句台词是否有当下目的并产生反应；
- 整场是否出现连续短问短答、话题句句闭合或人物只说结论的过度压缩；
- 是否存在替编剧保存伏笔、却不产生当前行为的“先记住/以后再查”式台词；
- 是否符合素人语料的自然来回；若本场属于举证或条件升级，再检查《刘熙的条件》的信息递进。

以上功能检查通过后，复检时不读取拓扑、情绪功能、后续反转、篇幅指标和作者意图，只携带相邻话茬、人物关系、当下目的与下一行动，按 `chinese-dialogue-craft.md` 的“最小上下文自然对白复检”逐句重读。校验者必须能直接说明每句在让对方回答或执行什么；存在更普通、更直接的日常说法时，使用普通说法。不得因为原句兼具施压、塑造人物或收尾功能而保留不自然表达。

记录至少覆盖话茬与当下目的、人物声音、设定发布与承重句、朴素中文四项。只写“PASS”“自然”“符合人物”或可用于任意剧本的套话视为没有执行校验。

### 因果与连续性校验

检查：

- 开场是否执行直接前置选择或结尾事件；
- 人物为何在场，是否拥有相应进入、查看、触碰或处置权限；
- 事件是否先发生并被感知，再产生人物反应和下一步行动；
- 人物是否让观众看懂他认为核心事件意味着什么；
- 核心关系或个人得失被触发时，是否实际驱动反应顺序和下一行动；
- 物件的来源、位置、移动路径和当前持有是否清楚；
- 人物位置、关系、已知信息、风险和道具状态是否连续；
- 生产卡规定的核心事件、路径状态、定性体验功能和结果是否由实际事件完成；
- 结尾是否真实产生后续节点的进入条件；
- 梗概和剧本是否覆盖同一段剧情。
- 梗概中的直接起因、压力和转折是否逐项在正文发生；
- 栽赃、偷换、潜入和关键物件移动是否具有可见接触机会与路径；
- 互动结果的差异是否兑现，汇合集是否只使用共同状态且下一行动在两路均已建立或由汇合集先建立；

记录至少覆盖上游事实、地点与权限、事件与反应链、物件与状态、后续进入条件五项。只写“PASS”“连续”“符合设定”或可用于任意剧本的套话视为没有执行校验。

两轮记录必须同时指向当前候选正文去除首尾空白后的同一 SHA-256，且未解决问题均为“无”。正文任何字符发生变化后，旧记录立即失效；即使只改一句对白，也要重新执行两轮。

## 七、自动修复

任一校验失败时，只解冻当前集的失败场次，优先执行：

- 删除重复解释和无行动作用的台词；
- 把说明改为可见事件、普通反应，或确实存在的劝阻、交换、掩饰、举证、逼问和自保；
- 把长独白拆成动作与短反应；只有真实对抗场面才拆成有抵抗的多轮来回；
- 保留必要承重句，其余改为普通接话和反应；
- 把承担多个戏剧任务的不自然表达改为当下最直接的请求、回答、拒绝或追问；可以删除时直接删除，不用另一句修辞性表达替换；
- 修正人物、场景、道具与前置状态的不连续；
- 删除仅为满足模板而添加、却不改变结果的冲突和角色功能；
- 补足核心事件中人物辨认意义、情感冲动和行动选择之间缺失的一步，不用解释关系的台词替代；
- 补演选择行为、即时结果或必要转场。

若失败来自人物权限、关键证据来源、世界规则或核心因果，不得用新增对白修补，直接返回生产卡。修复后按新正文重新运行因果连续性、动作可拍、最小上下文人话、对白可说与有限前情冷读，不得沿用修改前的任何 PASS。冷读一次修复仍失败，或既有语义校验连续两次仍失败时，检查生产卡是否不可执行；生产卡有问题则返回第一轮修订受影响节点及其依赖范围。

只有入口硬状态核对、机械门禁、两类复核和有限前情冷读全部通过，且记录指纹与当前正文一致，当前集才可冻结、生成观众摘要并回写真实结尾状态。定稿脚本只能验证已有证据并投射文件，不能自行填写语义 PASS。

## 八、制片格式

校验通过后使用普通 Markdown 逐行排版：

```text
# 第N集《标题》

单集梗概：本集梗概。

【场一 · 地点 · 日/夜 · 内/外】
出场：人物

△ 可拍摄的动作或环境变化。

人物：台词
```

Canvas 正文不使用代码块、表格、引用块或卡片。动作只写可拍内容，可承载连续动作；场与场之间由前场结果、问题或目标推动。

定稿中不保留“扩展场面”“收束场面”“补充场面”“加写”“返工”“优化后”“润色版”等修订标签。为通过完整度门禁补入的内容必须融入现有正式场次，或以包含地点、时间和内外景的标准场次标题新建场次；不得用粗体、Markdown 标题或说明词包装追加段落。
