# 分集画布生产协议

本协议规定从上游输入到最终完整剧本的唯一执行顺序。流程在一次任务中自动连续执行；流程图、内部批次、逐集校验和修复均不产生阶段性用户回复。

## 一、读取阶段资料

### 全局规划阶段

读取：

- `emotional-spine-and-branching.md`
- 悬疑、惊悚、犯罪、反转、秘密或证据延后揭露题材再读 `causal-clarity-and-suspense.md`
- `canvas-cache-protocol.md`

### 剧本执行阶段

读取：

- `script-execution-and-validation.md`
- `chinese-dialogue-craft.md`
- `gold-sample-episode.md`

不把所有资料同时加载到单场对白上下文。

## 二、输入与事实门禁

确认`游戏企划`、`角色描述`、`场景描述`和`道具描述`完整。

建立事实基线：

- 主角身份、处境、目标和不行动的后果；
- 主要人物欲望、关系、知情范围和隐瞒；
- 已发生的前史因果；
- 世界规则的可见效果、限制与代价；
- 场景入口、出口和固定连接；
- 关键物件初始来源、持有者和状态；
- 各结局结果、所得和代价。

输入冲突按用户明确内容优先、正式字段优先、具体描述优先于概括描述的顺序统一。仍有多种解释时，采用对核心目标、人物关系和既有资产改动最小的一种，并将假设写入隐藏缓存；不因中间冲突暂停整条生产流程。

## 三、全局情绪与拓扑

1. 根据游戏体量和结构信息确定节点数、正式结局和互动预算。
2. 先建立主干情绪脊，再设计节点和分支。
3. 每集记录情绪起点、变化原因和落点。
4. 每个选择记录即时行为、情绪/关系/风险差异和后续状态。
5. 调剂选择有不同即时结果后可较快汇合；重大选择直达结局或展开至少三个连续差异节点。
6. 所有节点、边和结局形成唯一拓扑。

情绪不能只靠氛围、台词或新线索变化；必须由获得、失去、关系、信息、风险或行动权变化造成。

## 四、建立画布缓存

按 `canvas-cache-protocol.md`：

1. 定位 Canvas。
2. 创建 `.episode-cache/`。
3. 写入 manifest、全局事实、拓扑、人物、物件和钩子缓存。
4. 为每个节点创建分集文件和生产卡。
5. 运行拓扑、情绪、因果、承接和梗概校验。

第一阶段失败时只修改缓存中的对应层，不进入完整剧本。

## 五、写入结构并继续

将冻结拓扑投射为：

- Mermaid 流程图；
- 全部分集编号、标题和单集梗概；
- 玩家可见选择和目标集。

写入 Canvas 公开层，不发送阶段性回复，立即进入完整剧本阶段。只有用户明确只要结构时，才以结构稿结束本次任务。

## 六、逐集滚动生成

按拓扑顺序逐集处理：

1. 读取当前滚动窗口和当前集实际资产状态。
2. 先按生产卡写连续戏。
3. 按中文对白规则调整台词。
4. 按普通 Markdown 转换为制片格式。
5. 将初稿写入当前分集缓存。
6. 调用两个独立校验任务：中文对白校验、连续性校验。
7. 失败时按建议修改失败场次并复检。
8. 通过后冻结当前集并回写真实状态。
9. 自动继续下一节点。

逐集写作不重新设计情绪脊、拓扑、人物弧光或结局。

## 七、逐集校验代理

### 中文对白代理

输入当前集定稿候选、人物关系和声音气质、当前题材素人语料、金标方法。只输出：

- PASS / FAIL；
- 失败场次；
- 承重句过密、设定发布会、人物趋同或不自然来回的位置；
- 具体修改方向。

### 连续性代理

输入所有直接前置真实结尾、当前生产卡、当前剧本、当前结尾和直接后续进入条件。只输出：

- PASS / FAIL；
- 人物、场景、物件、知情、关系、风险和情绪不连续的位置；
- 未执行的选择后果或未形成的后续条件；
- 具体修改方向。

复用两个校验线程，线程 ID 写入 manifest。子代理不直接编辑文件。

## 八、全剧压缩对齐

全部节点冻结后，从缓存生成：

- 人物轨迹；
- 道具与证据轨迹；
- 钩子抛出与回收轨迹；
- 各主要路径情绪轨迹；
- 下游字段覆盖表。

运行确定性脚本和独立语义校验。发现问题时确定依赖范围，只解冻并修复受影响节点及其直接后续。修复后重跑相关逐集与全剧校验。

## 九、最终投射与交付

从已冻结分集文件直接组装：

- `episode-script.md`；
- 每集下游自然参数；
- 必要时更新具有明确自动内容标记区的 `index.html`。

组装阶段不重新生成剧本，不改写已通过的分集。

用户完整稿必须包含全部节点和全部结局。隐藏缓存、生产卡和校验记录不向用户展示。默认最终回复一次性包含流程结构、梗概、完整剧本与结局；此前不发送完成提示或继续询问。
