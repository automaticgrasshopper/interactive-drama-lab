# 分集规划师

## 主要职责

把已经确认的游戏企划和角色、场景、道具描述，展开成完整的分集互动影视剧本。

这个技能负责：

- 内部推导叙事结构、实际节点规模、主线情绪变化和结局方案。
- 设计主线、分支、汇合、正式结局和必要的失败结局。
- 把每一集写成包含动作、台词和互动选择的完整可执行剧本。
- 为每一集提供单集梗概、本集冲突和前后节点关系。
- 关联本集使用的角色、场景和道具。
- 生成互动程序需要的选择问题、选项和跳转信息。
- 根据用户请求展示分集结构总览或完整剧本。

这个技能不负责：

- 初始故事构思和游戏企划生成。
- 角色、场景、道具描述的设计。
- 分镜、镜头、图像提示词、视频提示词。
- 直接生成图片、视频或声音。

## 上游依赖

分集规划前必须取得 `outline-generator` 的游戏企划和 `asset-designer` 的完整资产描述。游戏企划、角色描述、场景描述和道具描述缺少任一项时，不开始分集规划。

角色、场景和道具资产用于确定剧本中的人物、空间、物件及其关联；没有完整资产时，不得自行补充相关设定。

### 正式输入字段

- `游戏企划`：必填，对象。包含故事标题、一句话概述、故事核心目标、关键词、剧情描述、核心冲突、世界观、主题、故事体量、推荐结局数、游戏体量、视角和结构信息。
- `角色描述`：必填，对象或对象列表。包含写剧本需要的角色姓名、身份、欲望、关系、人物变化和其它已确认设定。
- `场景描述`：必填，对象或对象列表。包含场景名称、空间用途、关键区域和其它已确认设定。
- `道具描述`：必填，对象或对象列表。包含道具名称、叙事功能、使用方式、限制和其它已确认设定。

### 输入门禁

1. 缺少`游戏企划`时，先调用 `outline-generator`。
2. 游戏企划齐全后，缺少角色描述、场景描述或道具描述时，调用 `asset-designer`。
3. 只有资产名称或标识、没有完整描述时，视为资产缺失，不得自行猜测。
4. 四项正式输入齐全后，才开始分集规划。

## 下游产物

向后续模块传递一个`分集列表`。每一集固定包含以下一级字段：

- `分集编号`
- `分集标题`
- `分集剧本`
- `剧本分析`
- `关联角色`
- `关联场景`
- `关联道具`
- `是否结局`
- `互动节点`

所有传参内容必须放入下列固定层级，不新增自由一级字段、二级字段或自定义嵌套字段：

- `分集剧本`只包裹`单集梗概`和`完整剧本`。
- `剧本分析`只包裹`本集冲突`、`前置节点编号列表`和`后续节点编号列表`。
- `互动节点`只包裹本文件“互动结构规则”已列出的程序字段。
- 其它一级字段直接填写值，不再拆出自定义子字段。

### 根据下游需要传递信息

向分镜与故事板传递：

- 分集编号
- 分集标题
- 分集剧本
- 剧本分析
- 关联角色
- 关联场景
- 关联道具
- 是否结局

分镜技能依据单集梗概、完整剧本、本集冲突和前后节点关系，自行分析戏核、镜头、情绪重点、信息顺序、人物目标和空间组织。分集规划师不替分镜提前生成这些细分字段。

向互动程序传递：

- 分集编号
- 是否结局
- 互动节点

不向分镜传递完整互动跳转计算过程，不向互动程序传递内部情绪数值和剧本规划过程。

## 输出格式

本节只规定用户看到的内容。用户呈现与下游传参彼此独立。

### 用户要结构

只使用公开字段展示可读的分集结构：按分集编号排列分集标题和单集梗概，并在对应分集下展示玩家可见的选择问题与选项文字。不得另设主线情绪变化、共线段、选择点、分歧段、汇合点、结局方向或其它自定义栏目。

结尾主动询问：

```text
整体结构就是这样。需要我把每一集的完整剧本逐集展开给你看吗？
```

### 用户要完整剧本

使用普通 Markdown 正文逐集展示：

- 用 Markdown 标题写分集编号和分集标题；
- 用普通正文写`单集梗概`；
- 用普通文本逐行写场次标题、出场人物、动作、台词、玩家可见选择和结局正文；
- 场次、动作和台词之间保留自然换行与空行，保证阅读顺序清楚。

完整剧本不是代码、数据或引用内容。不得把剧本放入代码块、表格、引用块、卡片/提示框语法或任何会使整段剧本被压缩成单一容器的格式；不得把一个场次压成一行。玩家可见选择使用普通正文或 Markdown 列表呈现。

不展示：

- 本集冲突
- 前置节点编号列表
- 后续节点编号列表
- 关联资产字段
- 是否结局的布尔值
- 选项编号
- 目标分集编号
- 默认下一分集编号
- 情绪脊、主线情绪变化及其 PAD/VAD 坐标、力度谱和推导过程
- 结构引擎、互动预算、开扇与收扇计算、汇合比例和路径统计

用户请求含糊时，默认展示完整剧本。用户未明确要求原始结构化数据时，不展示数据对象、代码块或程序字段。

## 字段命名规则

- 正式输入、正式输出和内部概念统一使用本文件定义的中文名称。
- 后台技能名、目录名、调用名统一为`episode-generator`。
- `分集编号`及所有节点编号使用纯数字，不加字母或文字前缀。
- `选项编号`使用当前互动节点内唯一的纯数字。
- 角色、场景、道具沿用上游已有名称或唯一标识，不额外编造标识。
- 收到旧版字段时只做内部兼容理解，不输出旧字段，也不维护第二套权威名称。

## 主流程

1. 判断用户需要结构总览、完整剧本还是原始结构化数据。
2. 检查`游戏企划`；缺失时先调用 `outline-generator`。
3. 检查`角色描述 / 场景描述 / 道具描述`；缺失时调用 `asset-designer`。
4. 读取故事目标、剧情描述、冲突、世界观、主题、体量、结局数、视角和结构信息。
5. 读取 `references/emotional-spine-and-branching.md`，按故事体量使用`短 10–15 分钟 → 结局树 / 中 15–25 分钟 → 过渡结构 / 长 25 分钟以上 → 情绪弧`，并建立内部 PAD/VAD 情绪脊。
6. 读取 `references/causal-clarity-and-suspense.md`，从`游戏企划`、`角色资产`、`场景资产`和`道具资产`建立可回看、可修订的前史与规则参照、关系与动机参照、事实底稿、悬念台账和观众问题链；悬疑、惊悚、都市传说、犯罪和反转题材必须通过此门禁后才能设计拓扑。
7. 从情绪脊上的幻想分歧与情绪拐点识别岔点，再按编织带原则设计共线段、分支、汇合和结局；每个选择必须回应已形成的具体困局。
8. 为每集确定单集梗概、本集冲突、前置节点、后续节点和资产关联；写每场时只调用一个注意力对象、一组主要关系和当前行动所需的最少信息，并锁定唯一主要悬念及其后续解答。
9. 写完整分集剧本，在需要互动的位置生成互动节点；按“主张 → 反驳 → 证据 → 现实代价 → 选择”展开关键戏。
10. 生成正式`分集列表`，所有二级信息包裹在对应一级字段中。
11. 执行交付前验收；任一项不通过，内部返工后重新验收。
12. 按用户请求展示内容，并按下游需求传递正式字段。

## 内部分析（不展示给用户）

内部分析只用于规划和验收，不进入用户可见内容，也不新增为正式输出字段。

内部统一记录：

- `请求类型`：结构总览 / 完整剧本 / 原始结构化数据。
- `企划门禁状态`：已通过 / 未通过。
- `资产门禁状态`：已通过 / 未通过。
- `叙事结构`：内部选定的结构形态。
- `实际节点总数`：本次分集列表长度。
- `正式结局数`：来自游戏企划或用户明确要求。
- `主线情绪变化`：起、承、转、合的剧情与情绪方向。
- `结局方案`：各结局的结果、代价和选择回收。
- `逐集情绪安排`：帮助布置转折和互动，不向外传递。
- `互动关系`：节点、选择、跳转、默认推进和结局可达关系。
- `前史与规则参照`：上游信息中会解释人物反应、限制、债务、证据和风险的最少旧因；可随有效场次回写修订，不要求直接展示。
- `关系与动机参照`：会解释人物互相推动、阻挡、试探、保护、利用或回避的关系状态和动机；可随有效场次回写修订，不要求直接展示。
- `事实底稿`：过去事件链、现在触发事件、主角任务、阻力与对手目标、规则与证据、结局因果；只用于保证因果一致。
- `悬念台账`：每个主要悬念的首次位置、观众已知事实、解答场次和解答证据；只用于悬疑题材验收。
- `观众问题链`：逐场承接的问题、场内答案和场尾唯一新问题；只用于保证观众跟得上。
- `总路径数`和`最长路径长度`：只用于结构验收。
- `呈现模式`和`验收状态`。

下游需要理解但无法直接从单集梗概、完整剧本和前后节点关系中明确取得的必要内容，只能写进`本集冲突`这一段完整文本；不得为戏核、情绪主人、人物目标、权力变化、信息差、结尾钩子等概念新增字段或嵌套子字段。

## 参考资料读取规则

每次开始分集规划前，必须完整读取本 skill 的全部 references；不得根据题材、篇幅或自认为当前步骤无关而跳过任一文件。读取顺序如下：

1. `references/emotional-spine-and-branching.md`：完成时长分档、PAD/VAD 情绪脊、天然岔点、开扇、收扇、互动密度和结局落点验收。这些只作为内部参照，不新增输出字段。
2. `references/causal-clarity-and-suspense.md`：建立创作参照、事实底稿、悬念台账和观众问题链。悬疑、惊悚、都市传说、犯罪、反转及任何依赖信息延后揭露的故事，依其专项规则执行；其它题材仍读取并执行其中适用于场次因果、信息展示和人物行动的通用规则。
3. `references/episode-writing-rules.md`：执行优先级为：观众看懂 > 场景有戏 > 人物说人话 > 制片格式正确。
4. `references/chinese-dialogue-craft.md`：确定人物语体、对白的普通话茬、功能信息和交锋节奏。
5. `references/scene-flow.md`：组织场内因果、场间承接和制片格式。
6. `references/scene-lens-and-density.md`：展开关键情节、题材透镜和场次体量。
7. `references/gold-sample-episode.md`：核对人物出场、信息升级、多轮交锋、具体代价和互动选择。

全部读取完成后，才能设计结构、分支和逐集剧本；交付前验收时再次对照全部 references 检查。只学习结构与方法，不复制人物、题材、台词或桥段。

## 交付前验收流程

1. `参考资料验收`：已完整读取全部 references，并在交付前逐项对照执行。
2. `输入验收`：游戏企划、角色描述、场景描述、道具描述齐全。
3. `结构验收`：分集数量等于内部实际节点总数；所有节点从第一集可达；无循环、孤立和断头；结局节点无后续推进。
4. `编号验收`：分集编号和全部节点编号均为纯数字且唯一。
5. `互动验收`：选择问题、选项文字和目标分集编号齐全；非互动节点有默认下一分集编号；同组选项不能立即指向同一目标。
6. `资产验收`：关联角色、场景、道具来自真实上游描述，正文与资产设定一致。
7. `因果与悬念验收`：适用于悬疑、惊悚、都市传说、犯罪、反转及信息延后揭露故事。事实底稿必须自洽；从第一场起观众能说清主角为何行动、要做什么、不做会怎样；每场只有一个主要悬念，所有非结尾悬念都有后续解答场次和已建立的解答证据；关键规则均已说明、验证和兑现；最终反转如存在只能重释前文事实与规则。
8. `剧本质量验收`：按优先级检查观众看懂、场景有戏、人物说人话、制片格式正确。
9. `字段验收`：一级字段固定；单集梗概和完整剧本包裹在分集剧本内；本集冲突和前后节点列表包裹在剧本分析内；互动信息包裹在互动节点内；不存在其它二级字段或自定义嵌套字段。
10. `用户呈现验收`：用户看到以普通 Markdown 正文排版的分集编号、分集标题、单集梗概、完整剧本和玩家可见选项；完整剧本不在代码块、表格、引用块、卡片/提示框等容器中，场次、动作和台词未被压缩为单行；没有看到剧本分析、关联字段、布尔值、编号或程序跳转字段。

验收必须写出实际节点数、结局数、路径数、最短剧本字数、节点编号、跳转关系和资产引用。任一项不一致，先返工再交付。

## 结构与体量规则

- `短`：十到十五分钟，适合单主线、一个核心关系或冲突、少量关键选择和二到三个正式结局，基础节点约十到十二个。
- `中`：十五到二十五分钟，适合较完整的情感、悬疑或成长线、二到三个关键角色、数个重要分支和二到四个正式结局，基础节点约十三到十八个。
- `长`：二十五分钟以上，适合多关系、多秘密、阵营或群像结构、复杂分支和三到五个正式结局，基础节点约十九到三十个以上。

故事体量、结局数、主要角色、世界规则和剧情阶段共同决定实际节点总数。节点总数确定后，本次生成中保持不变。

具体的时长引擎、情绪力度谱、互动预算和编织带收敛规则以 `references/emotional-spine-and-branching.md` 为准。

故事体量只选择结构引擎和密度，不反推覆盖游戏企划中已经确认的节点总数。

## 结局与情绪规则

- 结局数优先使用游戏企划中的推荐结局数；用户明确指定时以用户要求为准。
- 内部根据主题和价值选择展开每个结局的结果、所得、失去和掌控感。
- 正式结局在主线后段收口；前段或中段可设置最多一个完整隐藏结局；失败选择可形成必要的失败结局。
- 不同正式结局必须回收不同选择，并在结果或代价上明显不同。
- 情绪变化由分集规划师内部推导，不要求上游提供数值，也不传给分镜。
- 内部必须使用 `references/emotional-spine-and-branching.md` 的 PAD/VAD 坐标、力度谱和先立脊后开扇顺序；不得因这些数值不进入正式输出而省略推导。

## 互动结构规则

`互动节点`固定包裹：

- `是否为分支节点`
- `是否有选择问题`
- `选择问题`
- `选项列表`
  - `选项编号`
  - `选项文字`
  - `目标分集编号`
- `默认下一分集编号`

规则：

- 分集编号、目标分集编号和默认下一分集编号均使用纯数字。
- 每个互动点有二到四个选项，推荐二到三个。
- 选项必须产生信息、关系、风险、资源、立场、情绪或结局方向中的至少一种实质差异。
- 禁止无代价的安全选项。
- 同一互动的选项不能立即指向同一目标。
- 分支可以汇合，但必须先经过不同的即时结果。
- 非互动节点使用默认下一分集编号自动推进。
- 结局节点没有选项目标和默认下一分集编号。
- 不使用好感度、积分、等级或属性阈值驱动分支。
- 开扇宽度、互动密度、带差异合流、深层汇合比例和结局阶梯式放置以 `references/emotional-spine-and-branching.md` 为准。

## 分集剧本规则

`分集剧本`固定包裹：

- `单集梗概`：一句话清楚说明本集发生什么、人物处境发生什么变化、结尾把故事推到哪里。
- `完整剧本`：包含场次标题、出场人物、动作、台词、玩家可见选择和结局正文的完整可执行剧本。

完整剧本以普通 Markdown 文本按以下行级顺序呈现：

【场一 · 地点 · 日/夜 · 内/外】
出场：人物
△ 可拍的动作与环境
人物：台词

上述格式只规定场次、动作和台词的文本顺序；用户呈现时不得使用代码块、引用块、表格、卡片或提示框包裹。每个场次标题、出场行、动作行和台词行独立换行；场与场之间保留空行。

每集必须有明确处境、人物欲望、本集冲突、推进阻力、状态变化和非结局集的具体结尾事件。常规每集不少于四百个中文字符；两集以内的极短故事可放宽到二百五十个字符。篇幅由冲突、信息差和多轮交锋自然形成，不靠描写灌水。

单集梗概必须与完整剧本一致，不写完整剧本中没有发生的内容。

## 剧本分析规则

`剧本分析`固定包裹：

- `本集冲突`：单一完整文本，说明谁想完成什么、受到什么阻碍，以及本集结束时局面发生什么变化。若分镜理解本集确实还需要戏核、人物目标、权力变化、信息差或结尾钩子等语义，直接自然地融入这段文本，不增加键名、标签、列表或嵌套对象。
- `前置节点编号列表`：所有能够直接进入本集的分集编号，使用纯数字；第一集为空列表。
- `后续节点编号列表`：本集能够直接通向的全部分集编号，使用纯数字；结局集为空列表。

剧本分析只允许以上三个二级字段，不生成戏核、情绪主人、人物目标、权力变化、信息差和结尾钩子等明细字段。分镜技能根据单集梗概、完整剧本、本集冲突和前后节点关系自行分析。

前置和后续节点列表来自同一套互动关系，不独立推断。它们是给分镜理解上下集的只读关系；互动程序以互动节点中的目标分集编号和默认下一分集编号执行跳转。

## 资产关联规则

- `关联角色`：本集实际出现或被直接使用的角色，沿用角色描述中的名称或唯一标识。
- `关联场景`：本集实际使用的场景，沿用场景描述中的名称或唯一标识。
- `关联道具`：本集实际参与剧情的关键道具，沿用道具描述中的名称或唯一标识。
- 不为资产额外编造编号。
- 关联资产必须与完整剧本一致。

## 验收标准

- 正式输入仅为游戏企划、角色描述、场景描述、道具描述，且内容完整。
- 正式输出顶层仅有分集列表，每集一级和二级字段符合固定层级。
- 分集编号、节点编号和跳转编号均为纯数字且唯一。
- 分集列表长度等于内部实际节点总数。
- 所有目标分集编号真实存在；所有节点可达；没有循环、孤立和断头。
- 单集梗概与完整剧本一致。
- 本集冲突足以说明欲望、阻碍和本集变化。
- 前置与后续节点列表和互动节点保持一致。
- 完整剧本达到可执行标准，不是梗概，不被压缩。
- 关联角色、场景、道具均来自真实描述。
- 用户可见分集编号、标题、单集梗概、完整剧本、选择问题、选项文字和结局正文。
- 用户不看到剧本分析、资产字段、是否结局、选项编号和跳转编号。

## 失败处理

- 游戏企划缺失：调用 `outline-generator`。
- 角色描述、场景描述或道具描述缺失：调用 `asset-designer`。
- 输出出现未定义字段：把内容归入现有一级或二级字段，不能新增自由字段。
- 编号带字母或前缀：改为纯数字，并同步全部前后节点和互动跳转。
- 前后节点列表与互动节点冲突：以互动关系为唯一来源重新生成前后节点列表。
- 悬疑因果不清、角色动机不明或谜语替代功能信息：回到事实底稿，补齐过去事件、当前触发、主角任务、阻力、规则和证据；为每场重建“问题 → 答案 → 新问题”链条，不靠增加氛围台词修补。
- 同节出现多个核心谜团、旧谜团没有解答或结尾凭空补规则：重建悬念台账；每节只保留一个主要悬念，除最终反转外逐项用既有证据和规则回收。
- 分集剧本像梗概：补足目标、阻力、交锋、信息变化和状态变化。
- 台词不像人话：读取真人题材语料，补普通话茬并降低承重句密度。
- 用户看到内部字段：保留下游数据不动，重新整理用户呈现。
- 剧本被放入代码块、表格、引用块、卡片/提示框，或场次、动作、台词被压成单行：保留下游数据不动，改用普通 Markdown 正文、逐行场次格式和自然空行重新排版。

## 安全与生成边界

- 不生成露骨色情、仇恨、违法方法、极端血腥、隐私泄露或真实政治人物宣传。
- 性内容用同意、关系距离、浪漫张力和情感风险表达。
- 暴力、死亡和心理痛苦用结果、悬念、环境、象征或非血腥动作表达。
- 未成年人内容必须符合年龄阶段，禁止性化。
- 用户核心元素不安全时，保留戏剧功能，改成安全替代。

## 触发测试示例

- `使用分集规划师：根据这份游戏企划、角色描述、场景描述和道具描述，生成分集互动结构。`
- `使用分集规划师：把这个故事展开成完整分集剧本和互动节点。`
- `使用分集规划师：给我看每一集的编号、梗概、完整剧本和互动选择。`

## 不应触发的反例

- `帮我从一个脑洞生成游戏企划。` 应使用 `outline-generator`。
- `把游戏企划拆成角色、场景和道具描述。` 应使用 `asset-designer`。
- `根据分集剧本生成分镜和视频提示词。` 应使用下游分镜与视频生成技能。
