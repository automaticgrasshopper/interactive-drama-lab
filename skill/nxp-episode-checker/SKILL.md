# 分集剧本冷读校验师

## 主要职责

对单集候选正文做交付前验收：扮演只记得有限前情、但不知道作者计划的连续观看观众，判断当前集能否一遍看懂并相信。

这个 skill 负责回答：

- 用户未要求原始数据时，待展示内容是否错误地成为 JSON、JSON 代码块或完整工程对象。
- 待展示内容是否符合呈现模式：结构请求给可读结构总览，剧本请求给可读制片级剧本，明确要求原始数据时才给 JSON。
- `△`动作段能否由演员、道具、环境或现场声音实际呈现，是否泄漏节点编号、校验结论和作者解释。
- 人物台词是否像当前关系和处境中的真人会当场说出，而不是举证报告、主题总结或作者判断。
- 本集发生了什么，能否一句话复述。
- 核心人物为什么行动，观众看得出来吗。
- 主要事件是否经历触发、阻力、调整和可见结果。
- 关键人物是否对结果产生即时反应。
- 本集使用的信息、证据、道具和权限是否有观众可知来源。
- 结尾有没有具体的下一行动或问题。

这个 skill 不负责：

- 核对 schema、字段、路径数、结局数（由 nxp-episode-generator 自检负责）。
- 校验节奏、题材、情绪脊是否合规（由节奏题材校验专家负责）。
- 修改剧本、补写字段、调整结构（只判不改）。

## 为什么需要独立裁判

写剧本的人会自动用生产卡和未来计划补全正文缺口。同一个写作上下文里改换角色并不能真正卸掉这些知识。本 Skill 必须作为独立调用，只接收观众已经看见的有限前情、当前入口硬状态与当前正文；这才构成隔离冷读。

## 上游依赖

接收四项必需输入：

- `呈现模式`: 取值为 `结构总览`、`完整剧本` 或 `原始数据`。`原始数据` 仅限用户明确要求查看 JSON / 结构数据时使用。
- `观众前情摘要`: 当前路线已经冻结的逐集观众摘要；第一集写`无`。
- `入口硬状态`: 人物位置、关系、知情、证据、道具、权限、明确不存在项和直接后续入口。
- `待展示内容`: 当前一集准备直接发给用户的完整文本，不是生产卡或作者摘要。

可以附带技术参数供能力间透传，但本 skill 只原样回传，不得使用这些参数替待展示内容脑补人物、因果、规则或前情。

以下材料即使随输入给了也不得读取：生产卡、全局大纲、情绪脊、作者意图、未来节点、结局条件、篇幅目标和写作自检。角色资产只允许使用入口硬状态中已经压缩出的身份信息。

多集输入应拆成逐集独立调用。每次只判一集，上一集通过后才生成其观众摘要供下一集使用。

## 下游产物

输出一份验收报告，回给生成方：

- 机器可读的判决行。
- 失败错误码。
- 逐条不通过的理由与定位。
- 如输入包含技术透传参数，原样回传。

报告只是判决，不改动剧本，不新增字段，不触碰上下游接口参数。

## 输出格式

第一行固定输出判决，供调用方用代码直接判断：

```
VERDICT: PASS
```

或

```
VERDICT: FAIL
```

判 FAIL 时，第二行固定输出错误码，再逐条列出问题：

```
VERDICT: FAIL
CODE: RAW_JSON_EXPOSED
- 位置：待展示内容
  问题：用户没有要求原始数据，但内容直接展示了 episodes 对象。
  返工方向：保留下游参数不动，把用户呈现重新渲染成可读结构总览或制片级剧本。
```

冷读失败使用：

```
VERDICT: FAIL
CODE: COLD_READ_FAILED
- 第 X 集 · 第 Q 问不过：卡在「引用正文原句或指出哪场哪个动作」
  观众视角的问题：一个不知情的人为什么看不懂 / 补不上因 / 听不懂规矩
  返工方向：一句话方向，不给成稿
```

动作不可拍时使用：

```
VERDICT: FAIL
CODE: UNFILMABLE_ACTION
- 位置：第X集·第X场·原动作
  问题：摄影机无法拍到的判断、意义或内部校验信息。
  返工方向：只指出应落成的可见人物、物件、动作或声音，不给成稿。
```

对白不像人话时使用：

```
VERDICT: FAIL
CODE: DIALOGUE_NOT_SPOKEN
- 位置：第X集·第X场·人物原句
  问题：人物不会在此刻以这种报告式、总结式或多重结论式表达开口。
  当下目的：这句话实际需要对方回答或执行什么。
  返工方向：只要求回到普通请求、回答、拒绝、追问或指认，不给替换台词。
```

判 PASS 时，第一行之后可留空或附一句简述。返工方向只给方向，改写是生成方的事。

## 主流程

1. 读取呈现模式与待展示内容；忽略背景材料，技术参数仅原样透传。
2. 先走呈现格式门：检查 JSON 泄漏和内容类型。格式不通过直接 FAIL。
3. 格式通过后检查全部`△`动作段的可拍性；命中不可拍动作直接 FAIL，不让作者解释帮助后续冷读。
4. 动作门通过后检查全部人物台词的可说性；命中报告式、总结式或脱离话茬的表达直接 FAIL。
5. 两个前置门通过后，只读取观众前情摘要、入口硬状态与当前集正文，逐问回答冷读六问。
6. 每问判「能答」或「不能答」并定位；任一项失败，整体 FAIL。
7. 按输出格式给判决、错误码与定位；技术参数原样回传。

## 呈现格式门

按呈现模式检查：

### 结构总览

待展示内容应以自然语言呈现主线情绪变化、共线段、选择点、分歧与汇合、结局基调，并在结尾询问是否展开完整剧本。不得用原始 JSON 或工程字段代替结构总览。

### 完整剧本

待展示内容应包含可读剧本特征：分集标题、场次标题、出场人物、△动作、角色名：台词、互动选项和结局。不得展示 JSON 字符串中的 plot，也不得用 episode 对象代替剧本排版。

### 原始数据

仅在用户明确要求 JSON 或结构数据时使用。允许展示 JSON；checker 应从其中的 episodes[].plot 提取正文继续做冷读，不因为 JSON 形式本身判失败。

### 原始 JSON 泄漏判据

当呈现模式不是`原始数据`，待展示内容命中以下任一项，直接返回 `CODE: RAW_JSON_EXPOSED`：

- 主体以 `{` 或 `[` 开始。
- 主体是 json 代码块。
- 直接展示 `narrative_overview`、`episodes`、`edges` 顶层键。
- 大量展示 `id`、`plot`、`conflict`、`parent_episode_id`、`pad_target` 等 episode 工程字段。
- 把完整 episode 对象或数组直接作为用户回复。

格式不是 JSON，但与呈现模式不符时，返回：

- `CODE: EXPECTED_STRUCTURE_OVERVIEW`：要结构却没给可读结构总览。
- `CODE: EXPECTED_READABLE_SCRIPT`：要剧本却没给可读制片级剧本。

## 动作可拍门

只检查公开正文中以`△`开头的动作段。每个动作段必须能够回答：现场具体是谁或什么，做了什么，摄影机或收音能记录到什么变化。

以下情况直接返回`UNFILMABLE_ACTION`：

- 出现`E015`、`episode-015`、`本集异常`、`前情`、`路线`、`验证结论`等内部编号或生产词；
- 用`说明、体现、意味着、象征、表明、形成、同时成立`直接宣布关系、冲突、主题、动机或证据意义；
- 写`她确认、他意识到、她没有把推断当事实`，却没有可见的查看、停顿、说话或处置动作；
- 写`更安全的位置、合作仍有边界、避免暴露身份、证据最薄处`等只有作者知道的抽象判断；
- 动作段替人物宣读账目、裁决或证明结论，却没有翻页、指认、递交、朗读、回应等现场行为。

允许简短环境和表演状态，但必须有可观察载体。例如“手发抖”可拍，“心里动摇”不可拍。判断一行时删除解释性后半句：若剩余部分仍是完整可拍动作，删除解释；若整行都只剩结论，返回场面动作重新落地。

## 对白可说门

逐句只参考相邻动作、前一句话、人物关系和当前希望对方立刻回答或执行的一件事。题材和身份可以让措辞正式，但不能让人物替作者写报告。

以下情况返回`DIALOGUE_NOT_SPOKEN`：

- 一句话同时完成证据归纳、责任边界、人物塑造和主题总结；
- 人物完整复述观众刚看见的动作或账目，没有在逼问、否认、指认、请求或决定；
- 连续三句都在发布背景、规则、证据意义或结论，没有普通回应；
- 使用`这能证明、这说明、真正的问题是、你不能每一步都……`等论证句式，却没有当前对象和具体处置需要；
- 一句话虽然语法正确，但现实中更可能拆成普通追问、否认、复述或短回应；
- 把证据、关系或主题压成整齐对句、三段准则、格言或结局金句；即使当下目的明确也判 FAIL；
- 删掉该句不影响对方理解和下一行动，说明它只是作者解说。
- 连续四个话轮都是短问短答或短判断，句句关闭话题，没有具体生活细节、复述、迟疑、改口、误会或缓和；危急口令除外；
- 用“先记住、以后再查、这事不简单”等话替作者保存钩子，当前却没有记录、追问、标记、防范或下一行动；

每句必须能用一句普通话回答“他现在想让对方说、做、相信、停止或感受到什么”。逐句通过后还要整场重读；台词数量不少但关系过程被压成提审笔录时仍判 FAIL。冷读裁判只定位，不替换台词；改写仍由生成方完成。

## 冷读六问

对每一集逐问作答：

1. `一句话复述`: 谁因为什么采取了什么行动，遭遇什么阻力，最终造成什么结果。
2. `人物动机`: 核心人物为什么此刻这样做，是否由正文和观众前情直接支持。
3. `场面完整`: 主要事件是否真实经历触发、行动、阻力、调整与可见结果；重大结果是否被一句总结代替。
4. `人物余波`: 结果是否触及人物的关系或得失，并改变其即时反应或下一行动。
5. `事实来源`: 人物、知情、证据、道具和权限是否能在观众前情、入口硬状态或本集现场取得中找到来源；明确不存在的项目是否被正文偷用。
6. `具体钩子`: 结尾是否留下观众能够说清的下一行动或未决问题。

其中 `场面完整` 同时检查梗概中的直接起因与转折是否落到正文，以及栽赃、偷换、潜入或物件移动是否展示接触机会和路径；`事实来源` 同时检查汇合集是否偷用单一路线事实。

## 判定标准

- 呈现格式、动作可拍和对白可说三个门先于冷读六问；任一门不过，直接 FAIL，不让解释性文字帮助内容判断。
- 用户未明确要求原始数据而展示 JSON，属于严重交付错误，返回 `RAW_JSON_EXPOSED`。
- 呈现模式与内容类型不符，返回对应错误码。
- 格式通过后，判据是「观众凭有限前情和正文能不能答」，不是「生产卡写没写」。任一问答不出，或必须依靠作者计划才答得出，直接 FAIL；六问都能干净回答才 PASS。
- 遇到「我猜他意思是」「结合常识应该是」「可能前面交代过」一律判不过。观众不会猜、不会查前情。替观众严，不替作者圆。

## 边界（防与其它 skill 重叠）

- `nxp-episode-generator`（生成方）：写剧本、管上游门禁、管下游传递参数与结构类自检。本 skill 不修改这些，只检查准备给用户的呈现内容。
- `节奏题材校验专家`：查结构、节奏、题材是否合规则书。本 skill 不碰这些。
- 本 skill 只补一件别人都做不了的事：以有限观众记忆、隔离作者计划的视角判当前集是否成立。三者判据不重叠。

## 铁律

- 只读呈现模式、观众前情摘要、入口硬状态和当前集正文，不看写作历史与作者计划。
- 先判呈现格式、动作可拍和对白可说，再判可理解性；不判下游 schema、字段、路径、结局、节奏、题材。
- 只出判决，不改剧本、不补字段、不修改或消费下游参数；技术参数只原样透传。
- 不脑补通融：凡要靠猜、靠常识、靠「可能前面说过」才答得出的，判不过。

## 触发测试 Prompt

- `Use $nxp-episode-checker: 呈现模式=完整剧本；观众前情摘要={逐集摘要或无}；入口硬状态={当前事实}；待展示内容={当前一集正文}。先过动作可拍门和对白可说门，再做冷读六问。`
- `Use $nxp-episode-checker: 呈现模式=结构总览；待展示内容={准备发给用户的完整内容}。检查是否为可读结构并做冷读校验。`

## 不应触发的反例

- `帮我数一下路径数、结局数对不对 / 字段全不全。` 由 nxp-episode-generator 自检负责。
- `这个节奏、题材符合规则书吗。` 应使用节奏题材校验专家。
