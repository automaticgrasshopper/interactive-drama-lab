## 二、已经确认的产品决策

1. 默认一步到位，不在流程图、梗概、执行组或逐集校验完成后询问是否继续。
2. 完整结果生成后再由使用者检查并提出修改。
3. 多个 Canvas 候选时不询问路径。先核对标题 slug、页面标题、任务关联文件和 manifest，只在匹配候选中按最近更新时间排序；没有匹配项则新建项目。
4. 流程图、公开逐集剧本和完整剧本汇总稿只写入 Canvas。最终消息只报告完成状态、校验结论和 Canvas 入口，不重复粘贴全文。
5. 隐藏缓存以 Agent 运行中便于持续读取和恢复为准，不进入公开页面。
6. 故事版通过同名输入字段直接接收每集九个锁定字段；内部缓存只是生产过程，不等于下游接口，也不进入公开 Canvas 或最终消息。
7. 内部状态使用自然中文固定栏目，不恢复 JSON 工作格式。

## 三、结构与梗概规则

1. 第一阶段先读取上游事实，用情绪脊辅助安排节点顺序、拐点、分支和结局，再建立唯一拓扑。
2. 情绪脊、PAD/VAD、互动预算和路径统计到拓扑冻结为止；内容阶段只接收节点的定性体验功能、入口事实、核心结果和出口条件。
3. 单集梗概使用一句冷静、客观、凝练的自然中文，写清人物为何在场、发生什么、如何反应、造成什么结果和下一行动；只有真实存在阻力时才写人物对抗。
4. 姓名首次出现时交代身份或关系；场景首次出现时交代性质、入口和进入原因；物件首次出现时交代来源、持有人或取得过程；规则首次使用时交代触发、可见作用和代价。
5. 不使用未建置的简称、能力名、场景名或道具名，不用作者判断代替可见证据。
6. 选项使用“动词＋明确对象”，只写玩家此刻执行的一个动作。
7. 选项目标集从选择当下开始，先演选择行为、人物反应和即时结果，再转场。
8. 调剂选择必须产生不同即时结果；重大选择直接进入结局，或展开至少三个连续差异节点。
9. 所有指向同一后续集的前置集都必须先兑现各自分支结果，并在进入汇合集前归一共同后续会用到的关系、信息、风险、承诺、道具、位置与下一目标；汇合集只允许一个统一开场和一份公开正文。若仍有差异必须影响后文，就延后汇合。
10. 关键节点执行题材透镜检查：题材独有的具体事件、既有规则内升级、下一行动或悬念三项齐全；异常必须写清位置、发现过程、可见作用和结果。
11. 第一阶段自检失败时返回事实、情绪脊、拓扑或生产卡重写，不把失败版本投射到公开层。

## 四、完整剧本规则

1. 第二阶段按戏剧执行组滚动生成，不按固定集数分批。
2. 选择与全部即时结果同组；汇合节点同时读取全部来路；最终选择与全部直接结局同组。
3. 每组只读取压缩全局事实、组内生产卡、入口真实结尾、出口条件、实际资产状态和相关未回收钩子，不重新读取主干情绪脊或 PAD/VAD 数值。
4. 每集先按场面本身选择事件驱动或对抗驱动的连续因果，再调整中文对白，最后转换为普通 Markdown 制片格式。
5. 每集执行中文对白和因果连续性双校验；执行组再检查互动兑现、分支差异、定性体验功能和结果力度。
6. 校验失败只修改失败场次或受影响节点；连续两次失败才返回生产卡。
7. 每集通过后回写人物、关系、知情、风险、道具和钩子状态，再冻结并继续。
8. 汇总稿由公开逐集文件按编号组装，不重新生成另一套正文。

## 五、中文语料规范

校验语料只使用以下名称：

- `iEdric/chinese-shortscript`

## 十一、v0.4 调优结论

本轮问题不是模型缺少常识，而是旧版多套局部规则同时争夺内容执行权：情绪脊数值、每场必须冲突、关系或权力必须变化、证据必须迫使行动、三类对白样例必须同时对照。模型为了满足可枚举检查，会优先拼装这些显式约束，压低本来能够自然完成的地点、权限、发现、反应和下一行动。

v0.4 采用以下分层：

1. 情绪脊只管理节点拓扑和节点的定性体验功能。
2. 生产卡只冻结入口事实、核心结果、路径状态和出口条件，不冻结逐个动作、反应和台词。
3. 梗概与正文先服从上游事实、普通现实和人物自然反应。
4. 事件驱动场面使用“正常状态—事件—感知—反应—现实处置—结果—下一行动”。
5. 对抗驱动结构只在人物目标真正冲突时使用。
6. 关系变化、权力翻转和互动选择都改为条件触发，不再作为每集硬指标。
7. 因果校验新增到场原因、行动权限、发现顺序、人物认知、物件位置与移动、下一行动等最低门槛。
8. 日常连接事实允许在内容阶段补足；新世界规则、关键证据、特殊权限、核心关系和事故真相必须返回生产卡。

第一集回归稿取消“记者直接进入警方现场”“第四名死者凭空出现”“红线逆水移动”“周既白被迫承担对抗功能”和“无真实两难却强行选择”等问题，改为第一发现人报警、刑警正常处置、亡者遗言生成具体下一目标，并以默认行动进入子时地铁站。

## 十二、v0.5 调优结论与完整回归

v0.4 的事实因果与权限校验通过后，连续测试仍出现“剧本能看懂事实，却感受不到人物关系”的问题。上游并不缺少“姐弟彼此深爱、姐姐是唯一亲人”等字段；失败原因是内容阶段把人物关系当连续性资料保存，没有把它激活为核心场面的行动动力。

v0.5 只增加条件性的情感逻辑层：

1. 核心事件触及亲人、承诺、创伤、身份或人物最在意的得失时，读取人物当前最怕失去、最想挽回和未解决心结。
2. 让这些事实改变人物最先注意什么、先说什么、身体如何反应和优先采取什么行动。
3. 若把核心关系人物换成陌生人后，台词与行动几乎不变，判定关系未进入场面。
4. 陌生观众必须能从画面与反应判断：发生了什么、人物认为这意味着什么、为何采取下一行动。
5. 普通过场、程序角色和不触发核心关系的场面不强制扩大情感，也不使用情绪数值倒推表演。

## 二十八、工具端同 Skill 输出未执行真实门禁

用户在另一工具中使用同名 Skill 生成《雾城夜行》19集剧本。该稿每集去空白可见字符为365—544，动作段为4—9，19集全部低于v0.1.12默认的850—1300字符和16—24动作段门槛。该稿还包含未经上游提供的核心人物关系、世界规则、关键道具能力和持续出场角色，并将“若此前”“某路线中”等内部状态说明直接写入公开剧本。

结论：同一 Skill 可以产生不同剧情，但不应产生不同的通过标准。该工具稿在第一道机械门禁就必须失败；若界面声称已通过，说明目标环境未完整执行当前验收链，可能是加载了旧副本、只把 Skill 当作提示词，或未实际运行缓存、指纹和确定性脚本。单看剧本无法唯一确定具体原因。

后续工具端回归不只检查最终文本，还必须核对：`episode-cache-v0.1.12`版本记录、Canvas外私有缓存、每集真实初稿与定稿、机械度量、两轮复核指纹、冻结状态和最终确定性验证结果。没有这些执行证据时，模型自述的“已校验”不构成通过依据。
