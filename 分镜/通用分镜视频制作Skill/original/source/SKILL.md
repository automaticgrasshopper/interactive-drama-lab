# 规划故事板及生成视频

## 目的

把已规划的剧集内容转化为视频内容的导演链路：

1. 剧集故事板。
2. 基于剧集故事板相邻 clip 的内部分镜拆分计划。
3. 每个 shot 对应的分镜视频生成prompt。
4. 使用剧集故事板作为参考生成的分镜视频。


## 必读 Reference

按步骤加载 Reference，避免一次性把所有细则塞进主流程：

- `references/director-guide.md` 只提供导演方法，不负责业务调度。剧集导演规划读取其中“1.1 剧集故事板阶段”，Shot 拆分读取“1.2 Shot 拆分阶段”，视频 Prompt 读取“1.3 视频 Prompt 阶段”，并按各阶段引用的关键方法继承同一份导演规划。
- 写剧集故事板图片生成提示词、版式、配色、画格比例、视角约束和 clean reference 视觉规则时，读 `references/storyboard-prompt-rules.md`。
- 剧集故事板生图前，读取 `references/episode-storyboard-to-video-split-plan-guide.md` 的“生图前 Clip 承载预检”；故事板生成并发送到当前对话后，再按该文件制定 Shot 拆分计划、确认来源 Clip 范围、写分镜视频生成 Prompt，并处理节奏与 Reference。
- 定义工程落库字段、输入输出字段名、类型和层级关系时，必须读 `references/business-interface.md`；正式字段合同以该文件为准。

## 输入

正式输入字段、必填关系、字段层级和资产 ID 规则以 `references/business-interface.md` 为准。执行时先读取该文件，不在 `SKILL.md` 中重复维护字段合同。

## 输出

正式输出字段只遵守 `references/business-interface.md`。过程结果可以用于执行和日志，但不作为顶层正式输出返回。生成后的图片、prompt、视频由 Agent 写入项目文件，工程侧再赋予对应 ID。

## 故事板对话展示

- 剧集故事板图片生成完成后，由 Agent 在当前对话中发送一条包含故事板图片本身的可查看图片消息，让用户直接看到本次生成结果。
- 故事板图片消息发送成功后，以该版本作为后续 Shot 拆分和视频生成输入，继续执行核心流程。
- 用户主动要求修改故事板时，完成修改并在当前对话中发送可查看的新版故事板图片，后续流程使用最新版本。

## 核心流程

1. **读取字段合同**：按 `business-interface.md` 校验输入、资产名称与 `ref_id` 层级和正式输出字段。
2. **资产预检**：确认本集需要的角色、场景和道具资产可用，并从项目文件读取唯一的项目级 `视觉风格`；角色已绑定 `音色ID` 时，确认该音色可解析到音色库试听音频，并在生视频时把试听音频作为该角色的声线 Reference 实际传入。试听内容不要求与本集台词一致；不得因此跳过声音 Reference、生成静音视频、临时猜声或换声。缺失时只返回真正缺失的资产和下一步资产任务。重新生成故事板、Prompt 或视频时继续使用项目文件中的同一视觉风格，不询问用户、不重新确认、不临时替换。
3. **剧集导演规划**：从完整 `分集剧本` 开始，按 `director-guide.md` 的“1.1 剧集故事板阶段”依次完成剧本解读、场景划分、场景固定设定、戏剧与人物调度、声音与摄影覆盖和 Clip 规划；每个 Clip 只确定关键发展、代表性定格状态和必要声音落点，不预测秒数，也不考虑后续 Shot 如何组合。完整导演规划作为本集共享过程结果保留。
4. **一次性定稿预检**：生图前按 `episode-storyboard-to-video-split-plan-guide.md` 的“生图前 Clip 承载预检”，同时读取完整 `分集剧本` 和导演规划，对 Clip 清单做内部通过/拆分判断。发现剧情覆盖缺失、单个 Clip 无法由一个下游 Shot 自然承载、一个画格混入多个时间状态或相邻状态无法连续时，立即修正 Clip 规划并重新预检；不制定 Shot 组合、不输出 Clip 秒数或时间码。全部通过后锁定本版 Clip 清单。
5. **生成并发送剧集故事板**：读取通过预检的完整导演规划和 `storyboard-prompt-rules.md`，只把已经锁定的 Clip 规划组装为剧集故事板图片提示词，不在提示词组装或生图阶段临时增删 Clip；完成后由 Agent 在当前对话中发送包含故事板图片本身的可查看图片消息，并以该版本继续后续流程。
6. **制定内部分镜拆分计划**：按 `director-guide.md` 的“1.2 Shot 拆分阶段”，同时读取完整导演规划、`分集剧本`、当前剧集故事板和 `episode-storyboard-to-video-split-plan-guide.md`，先标记必须切开的硬边界，再在每个连续区间内组合相邻 Clip，形成内部 Shot 计划和同集连续性链，并为每个 Shot 独立撰写故事化 `分镜描述`；完成后建立 `Clip -> Shot` 唯一映射，只有全部 Clip 按原顺序各映射一次且没有遗漏、重复时才能进入分镜槽位初始化。Clip 边界和画面切换不默认等于 Shot 边界，连续台词或声音不因切换画面被错误拆开，该计划不作为正式输出。
7. **初始化全部分镜槽位**：拆分计划通过对应 Reference 的执行门槛后，立即按拆分顺序为每个 shot 分配稳定 `分镜编号`，一次性创建同长度、同顺序的完整 `prompt列表` 和 `视频列表` 占位，并将拆分计划中的 `分镜描述` 写入对应槽位；列表长度即本集分镜总数，未完成项也必须显示。
8. **并行生成 Prompt 并流水生成视频**：按 `director-guide.md` 的“1.3 视频 Prompt 阶段”为每个 Shot 并行生成 Prompt。创建任务时，只把当前 Shot 的拆分记录作为不可变输入；任务可以读取共享导演规划，但不得从完整拆分计划中自行选择 Shot。Prompt 写回、视频任务启动和视频结果写回均以该记录的 `分镜编号` 定位，不使用数组下标或任务完成顺序；Prompt 中的来源 Clip 范围与当前记录不一致时，保留对应槽位为 `null` 且不启动视频。画面与声音分别规划，不修改 Shot 边界、补写剧情或回填 `分镜描述`；其他任务未完成或失败不阻塞已通过检查的分镜，失败和未完成项不删除、不追加、不重排。
9. **最终总览**：所有可执行任务完成后，只给简短结果总览；失败项保留原分镜槽位，不删除、不追加、不重排。

## 执行原则

- `SKILL.md` 只负责调度；字段、故事板、拆分、视频 prompt、质量和安全规则均以对应 Reference 为准。
- 每个阶段开始前先执行对应 Reference 的门槛检查；门槛不通过时，停在当前阶段并返回可执行的补充任务。
- 不把分镜拆分计划、生成参数、文本与 Prompt 检查或中间推理作为正式顶层输出。
